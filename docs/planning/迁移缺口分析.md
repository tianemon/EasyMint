## 二、agent-service.ts — 逐函数映射

> 882 行，是整个迁移最复杂的文件

### 2.1 `getQuery()` → 删除

```typescript
// Claude SDK（原有）
type QueryFn = typeof import("@anthropic-ai/claude-agent-sdk").query;
let _query: QueryFn | null = null;
async function getQuery(): Promise<QueryFn> {
  if (!_query) {
    _query = (await import("@anthropic-ai/claude-agent-sdk")).query;
  }
  return _query;
}
```

**Pi 替代**：`getQuery()` 不存在了。Pi 的会话模式完全不同：

```typescript
// Pi SDK（新）
// 初始化时创建 ModelRuntime + SessionManager，持久化复用
const sessionManager = SessionManager.create(cwd, sessionDir);
const { session } = await createAgentSession({ ... });
await session.prompt(text);  // 发送消息
```

**影响范围**：所有调用 `getQuery()` 的地方（约 5 处）改为调用 `session.prompt()`。

### 2.2 `createMessageChannel()` → 删除

```typescript
// Claude SDK（原有） — 长生命周期 AsyncGenerator 通道
interface MessageChannel {
  enqueue: (msg: SDKUserMessage) => void;
  generator: AsyncGenerator<SDKUserMessage>;
  close: () => void;
}
function createMessageChannel(signal: AbortSignal): MessageChannel { ... }
```

**Pi 替代**：不需要。Pi 的 `session.prompt(text)` 一次 = 一轮对话，`session.steer(text)` 可以在回合中注入消息。

| Claude 场景 | Pi 替代 |
|-------------|---------|
| `channel.enqueue(userMessage)` | `session.prompt(text)` — 开始新回合 |
| `channel.generator` 喂给 `query()` | 不需要，`session.prompt()` 内部处理 |
| `channel.close()` | `session.dispose()` |
| 中断后再发消息 | 无需 channel，直接再调 `session.prompt()` |

### 2.3 `buildQueryOptions()` → `buildPiSessionOptions()`

```typescript
// Claude SDK（原有） — 构建 query() 的 Options 对象

  : QueryOptions {
  return {
    cwd, permissionMode, model, env,
    systemPrompt: { type: "preset", preset: "claude_code", append: customPrompt },
    agents: { ... },
    mcpServers: { ...builtinMcpServers... },
    hooks: { PreToolUse: [...] },
    canUseTool: async (...) => { ... },
    pathToClaudeCodeExecutable: "...",
    ...overrides,

```

**Pi 替代**：拆分为几个独立部分：

| Claude Options 字段 | Pi 对应 | 说明 |
|---------------------|---------|------|
| `cwd` | `createAgentSession({ cwd })` | 直接传给 createAgentSession |
| `permissionMode` | Pi Extension 的 `ToolExecutionMode` | 步骤五评估，可暂用默认 |
| `model` | `createAgentSession({ model })` | 直接传 |
| `env` | `ModelRuntime` 注册 provider 时通过 `apiKey`/`baseUrl`/`headers` 设定 | 原逻辑保持，改注册方式 |
| `systemPrompt: { append }` | `DefaultResourceLoader({ systemPromptOverride })` | `prompts.ts` 组装逻辑 port 到 override 回调 |
| `agents: { ... }` | `agent-templates.ts` 保留，通过 systemPrompt 注入 | 步骤五适配 |
| `mcpServers` | `customTools: [...]` + `defineTool()` | EM 产品工具用 defineTool 重建；如有外部 MCP 则用 MCPManager |
| `hooks: { PreToolUse }` | Pi Extension Hook 系统 | 步骤五评估，可能不需要（Pi 有自己的权限系统） |
| `canUseTool` | Pi Extension 的 Hooks / `autoApprove` | 步骤五 |
| `pathToClaudeCodeExecutable` | **删除** — Pi 无 CLI binary 依赖 | 进程内运行 |

### 2.6 `startChatLoop()` → 删除

```typescript
// Claude SDK（原有） — 约 200 行的 for-await 循环
private startChatLoop(chat: ActiveChat, options: QueryOptions): void {
  // 1. getQuery() → query(chat.channel.generator, options)
  // 2. for await (msg of query) { ... }
  // 3. toStreamEvent(msg) → 转为 StreamEvent
  // 4. broadcast 到前端
  // 5. 处理 system/init 事件
  // 6. 处理 result 事件 → 上下文检测 → compact
  // 7. 捕获错误
}
```

**Pi 替代**：`session.subscribe()`，无需手动循环：

```typescript
// Pi SDK（新）
session.subscribe((event) => {
  switch (event.type) {
    case "message_update": /* 累计全文 → 前端 */ break;
    case "message_end":    /* 最终消息 → 前端 */ break;
    case "agent_end":      /* 回合结束 → 发送 result */ break;
    case "tool_execution_update": /* 工具进度 */ break;
    case "auto_compaction_start": /* 上下文压缩开始 */ break;
    case "auto_compaction_end":   /* 上下文压缩结束 */ break;
  }
});
```

### 2.7 `toStreamEvent()` → `event-bridge.ts`

```typescript
// Claude SDK（原有）
function toStreamEvent(msg: SDKMessage, runId, sessionId, source): {
  // 将 SDKMessage（Claude 格式）转为 StreamEvent（前端格式）
}
```

**Pi 替代**：在 `event-bridge.ts` 中集中处理，`AgentSessionEvent` → `PiChatEvent`（新前端格式）：

| Claude SDK 事件 | Pi 事件 | 前端 PiChatEvent |
|-----------------|---------|-----------------|
| `SDKMessage.type: "system" subtype:"init"` | `session.sessionId` | `{ type: "session_id", sessionId, chatId }` |
| `SDKMessage.type: "assistant"` + delta | `message_update` (累计全文) | `{ type: "message", blocks, partial: true }` |
| （无 delta — 最终消息在 message_end） | `message_end` | `{ type: "message", blocks, partial: false }` |
| `SDKMessage.type: "result"` | `agent_end` | `{ type: "turn_end", usage }` |
| `SDKMessage.type: "system" subtype:"tool_progress"` | `tool_execution_update` | `{ type: "tool_progress", toolName }` |
| `SDKMessage.type: "system" subtype:"compacting"` | `compaction_start` | `{ type: "compacting" }` |
| 无（EM 自建总结逻辑） | `compaction_end` | `{ type: "compacted", summary }` |
| `SDKMessage.type: "user"` — 跳过 | — | — |
| 异常处理 | `agent_end` + error | `{ type: "error", message, canRetry }` |

### 2.8 上下文压缩 → Pi 原生

```typescript
// Claude SDK + EM 自建（原有）
// startChatLoop 中的 result 事件 → getContextUsage() → 超阈值 → 
// 调用 buildContextHandoffPrompt() → channel.enqueue(summary) → 
// compactCount++ → 超过 MAX_COMPACT → archiveSession() + rotateSession()
```

**Pi 替代**：`SettingsManager.inMemory({ compaction: { enabled: true } })`，监听事件：

```typescript
session.subscribe((event) => {
  if (event.type === "compaction_start") {
    // 发前端 "正在压缩上下文..."
  }
  if (event.type === "compaction_end") {
    // event.result.summary → 前端
    // event.result.estimatedTokensAfter → 前端
  }
});
```

**缺口**：EM 原有的"超次数后归档旧会话+开启新会话"轮转机制，Pi 原生没有。需要评估是否保留此行为或信任 Pi 的原生压缩。

## 五、hooks.ts — 评估 Pi 替代方案

> 143 行

### 5.1 现有逻辑

```typescript
// Claude SDK（原有）
import type { HookInput, PreToolUseHookInput } from "@anthropic-ai/claude-agent-sdk";

// 4 条校验规则，通过 buildQueryOptions 中的 hooks.PreToolUse 注入：
// 1. set_task_status → building 时，不能有其他任务在 building/evaluating
// 2. set_project_stage → done 时，所有任务必须 done 或 failed
// 3. set_task_status → evaluating 时，目标必须 building
// 4. set_task_status → failed 时，目标必须 building 或 evaluating
```

### 5.2 Pi 中的对应机制

Pi SDK 有 Extension Hook 系统，在 `ToolExecutionStartEvent` 时可以介入：

```typescript
// Pi Extension Hook（新）
import type { Extension, ToolExecutionStartEvent } from "@earendil-works/pi-coding-agent";

const validatorExtension: Extension = {
  name: "easymint-task-validator",
  hooks: {
    onToolExecutionStart: (event: ToolExecutionStartEvent) => {
      // 校验逻辑在这里
      if (event.toolName === "set_task_status") { ... }
    },
  },
};
```

**缺口评估**：
- Pi 的 Hook 机制**可以**实现这 4 条校验规则
- 但接入点不同：原有是 SDK Options 中的 `hooks`，Pi 是 Extension 系统
- 复杂度：中（需要理解 Pi Extension 生命周期）
- **建议**：步骤三/四先不做 hooks，步骤五再实现

### 6.1 核心变更

| 原有逻辑（Claude SDK） | 新逻辑（Pi SDK） |
|------------------------|-----------------|
| `StreamEvent` 类型（来自 SDK） | `PiChatEvent` 类型（来自 event-bridge） |

| `normalizeEvent(ev)` → `StreamEntry`（在 StreamPanel 中） | **删除** — Pi 事件已归一化 |
| `processedSeqRef`（Set\<number\>）去重 | **删除** — 无需 seq 去重 |
| Effect A：启动时 `getBufferedStream` 回放 | 保留但简化（不再需要去重逻辑） |
| Effect B：实时 `onStream` 订阅 | 保留但简化 |
| `appendAiEntry(content)` — 尾部追加 delta | `replaceAiMessage(blocks)` — 全文替换 |
| `updateStreamStatus` 中的工具名映射 | 改为 Pi 工具名映射表 |

### 6.2 消息流转对比

```
原有：
  Claude SDK → IPC agent:stream → ChatPanel.onStream → normalizeEvent → StreamEntry
       ↓                                                                    ↓
  stream回放 Effect A ← seq去重(processedSeqRef) → Effect B 实时 ← onStream

       appendAiEntry ← delta ─────────────────────┘

Pi 新：
  session.subscribe → event-bridge → IPC agent:stream → ChatPanel.onStream
       ↓ (50ms合并)
  message_update（累计全文） → replaceAiMessage → React re-render
```

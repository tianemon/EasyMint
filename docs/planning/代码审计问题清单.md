## 二、剩余问题（38 项）

### 🟡 中等 — 9 项

#### M4 — Electron sandbox 未启用
**文件**：`app/main/index.ts`  
**现状**：`webPreferences.sandbox: false`，渲染进程持 OS 级默认权限  
**风险**：XSS/供应链攻击可突破到系统层  
**修复**：启为 `sandbox: true`  
**顾虑**：需完整回归测试所有 IPC 调用，可能大范围失效

#### M5 — Preload 攻击面过大
**文件**：`app/preload/index.ts`  
**现状**：暴露 100+ IPC 方法（文件读写/Shell/进程控制/项目删除/MCP 配置修改）  
**风险**：渲染进程中任何漏洞都可能做严重破坏  
**修复**：逐个排查前端实际调用，删除未使用的 API  
**顾虑**：误删必崩溃，需精确比对

#### M6 — @playwright/mcp@latest 供应链风险
**文件**：`app/main/services/mcp-service.ts`  
**现状**：`seedDefaultMcp` 用 `@latest` 标签，自动从 npm 拉最新版  
**风险**：npm 包被篡改的可能性虽小但不为零  
**修复**：锁定到固定版本号  
**顾虑**：需手动维护版本升级

#### M7 — MCP config 与 CC 共享
**文件**：`app/main/services/mcp-service.ts`  
**现状**：从 `~/.claude/.claude.json` 读取 MCP 配置，用户或恶意进程可修改  
**风险**：注入任意命令作为 MCP 服务器执行  
**修复**：复制到 `~/.easymint_pi_core/` 独立管理  
**顾虑**：用户需手动迁移已有配置

#### M8 — parallel.ts 未清理资源
**文件**：`app/main/services/task/parallel.ts`  
**现状**：`firstErrorPromise` 在所有 worker 成功后永久 pending（微量内存泄漏），`abortController` 也未清理  
**修复**：worker 全部成功后 resolve/abort  
**风险**：极低

#### M9 — event-bridge coalescer timer 异常路径残留
**文件**：`app/main/services/event-bridge.ts`  
**现状**：`flush()` 未被调用时 timer 不会清除  
**修复**：添加 `dispose` 方法  
**风险**：极低

#### M10 — pi-init 单例无并发保护
**文件**：`app/main/services/pi-init.ts`  
**现状**：check-then-initialize 模式，两个 IPC 同时触发可能双重初始化  
**修复**：用 Promise 锁  
**风险**：仅浪费资源不崩溃

#### M11 — process-service kill 失败未恢复
**文件**：`app/main/services/process-service.ts`  
**现状**：先 delete 再 kill，kill 失败时 Map 已删但进程仍在  
**修复**：先 kill 再 delete  
**风险**：低

#### M12 — Preload API 前端未调用
**文件**：`app/preload/index.ts`  
**现状**：`agent.steer`、`agent.followUp`、`agent.compact`、`agent.cycleModel`、`agent.setActiveTools` 等在 preload 暴露但前端从未调用  
**修复**：注释加 TODO 标记  
**风险**：无

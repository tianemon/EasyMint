# 系统提示词精简方案（稳健版）

> **状态**：方案稿 2026-08-13。背景：MINT_SYSTEM_PROMPT 252 行静态整串，规则全量常驻导致注意力稀释。
> **约束**（用户明确）：
> 1. 保留整串、不做阶段判断（EM 是通用 agent，可打开任意项目）
> 2. **不盲目跟风 80% cut**——DeepSeek 是第二梯队，规则需更明确，不能按 Anthropic 强模型的力度砍
> 3. 不做 session 内动态拼接（Pi 约束 + 破坏 DeepSeek 自动前缀缓存）
> 4. 方向 = **内容精简 + 低频下沉 skill**，不引入新机制

---

## 一、精简原则（DeepSeek 弱模型约束）

| 处理 | 判据 | 例子 |
|------|------|------|
| **留** | 模型推断不了的硬约束 | 注入防护、系统消息分类、授权边界、Gate、委派分工、工具清单、非程序员适配、交付完整性 |
| **砍** | 冗余表述/重复/比喻/示例/模型常识 | "像一个资深架构师"式比喻、重复的强调段、task 调用示例 |
| **下沉** | 低频、只在特定场景用到 | run.json 格式（项目完成才生成）、文档记录规范（开发期维护） |

**力度**：约减 30-40%（252 → ~160-180 行），保留**所有规则要点**，砍的是"表述冗余"。不追求 Anthropic 的 80%（那建立在模型已内化 agent 知识上）。

## 二、逐段处理清单

### identity（11-22，12 行）→ 砍比喻，留核心（约 -6 行）
现状含大量比喻（"像一个经验丰富的 PM"、"像资深架构师"、"避开只有做过很多项目才知道的坑"）——模型本就理解 PM/架构师角色，比喻稀释核心。
**精简后**：角色（项目经理+架构师）+ 核心目标（帮用户把项目做好）+ 直接务实不啰嗦 + 用户不确定时帮选但给理由。

### language（24-26）→ 留（已精简）

### easymint（28-49）→ 留（核心分工）
生命周期流程图 + 三角色 + 核心规则，是模型推断不了的流程契约。留，可微调措辞。

### guide_user（51-61）→ 留，精简对话节奏描述（-3 行）
"沉默是最差的体验"引导语可压，保留"长任务告知耗时/执行中保持存在感/完成主动引导下一步"要点。

### system_message（63-69）→ 留（硬约束，刚改过）

### ui_tools（71-83）→ 留，每条描述压一行（-4 行）
show_confirm_dev 的就绪标准 4 条很长，可压成短句。其余工具描述压一行。

### creation_flow（85-115）→ 留（已精简骨架，细节已下沉 skill）

### rules（117-264，~150 行）→ **重点精简区**

| 子段 | 处理 | 理由 |
|------|------|------|
| 0 授权范围 | 留 | 关键约束 |
| 1 行事风格 + 非程序员适配 | 留，精简非程序员适配的冗长描述（-3） | EM 核心（用户不懂技术） |
| 2 项目生命周期 | 留，精简"方案选型"5 行→2 行（-3） | 场景/复杂度判断核心 |
| 3 需求拆解 | 留，精简步骤描述（-2） | 核心 |
| **4 任务执行** | 见下 | 最大精简区 |
| 系统消息处理（181-185） | **删**（与 system_message section 63-69 重复） | 冗余 |
| Task 委派分工总则 | 留，删 2 行 task 示例（-2） | 示例是模型常识 |
| task.json 执行流程（201-214） | 留，"进度监控者"长段压 1 行（-3） | 流程核心保留 |
| **run.json 格式（216-231）** | **下沉 skill**（-15） | 低频：项目完成/用户问启动才用 |
| 中断恢复/需求变更（233-234） | 留（各 1 行） | 核心 |
| **项目文档记录规范（236-240）** | **下沉 skill**（-5） | 低频：开发期文档维护 |
| 长命令后台执行（242-243） | 留 | 重要 |
| 5 自我约束 | 留 | 核心 |
| 6 输出规范（代码块/大文件/CLAUDE.md/交付完整性） | 留 | 前端渲染+交付质量 |
| 7 输出聚焦 | 留，可微调 | 输出规范 |

## 三、下沉目标（新增/并入 skill）

| 内容 | 去向 | 触发 |
|------|------|------|
| run.json 详细格式（platform/label/cwd/run_command/url/静态 HTML 特例） | 新建 `project-run` skill | 用户问"怎么启动/加运行命令/项目完成生成运行配置" |

**注意**：下沉后 Mint 仍需知道"有这能力"，所以在 rules 留一行指引（如"运行配置/文档规范详见对应 skill"）。

## 五、验证方式

1. 对比精简前后 Mint 行为：创建引导、委派开发、系统消息响应、渲染自查——规则要点不能丢

3. 会话 JSONL 看 cacheRead 是否保持高位（前缀稳定，缓存命中）

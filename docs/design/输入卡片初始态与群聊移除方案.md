# 输入卡片初始态 & 群聊移除方案

> 状态：已定稿待实施（2026-08-14）
> 背景：默认打开 EM 时右侧空容器应直接显示输入卡片（不新建 tab/会话），用户输入消息时才打开新 tab；同时彻底移除已无作用的群聊模式。

---

## 一、输入卡片初始态

### 现状问题
- 初始打开 EM（无 tab）时，`tabs.length === 0` 渲染空 `EditorPanel`（Monaco 编辑器，无文件）——用户看到的是无意义的空编辑器
- 角色选择放在 ChatPanel 空状态里，未与"新建入口"统一

### 目标交互
```
初始打开 EM（无 tab）
  └─ 右侧显示「输入卡片」（居中）：
     ├─ Agent能力： [默认] [增强UI设计]（胶囊，上方）
     ├─ 小字说明：选择之后整个会话固定能力
     └─ 输入框 + 发送按钮
          │
          └─ 用户输入消息 →
              ① 新建 tab + 会话（带入角色选择）
              ② 角色选择消失 + 输入卡片下移动画 → 常规聊天页
              ③ 消息发送、Mint 回复

点「新建会话」按钮 → 打开新 tab，UI 与初始打开一致（输入卡片居中，发送后下移）
点历史会话 → 照旧：打开新 tab 加载旧会话（不走卡片）
```

### 关键设计
1. **初始空态替换**：`tabs.length === 0` 时不再显示空 EditorPanel，改为独立「输入卡片」组件
2. **新建会话 tab 空态**：ChatPanel `hasMessages === false` 且全新会话时，显示同样输入卡片（居中），发送后下移
3. **下移动画**：输入卡片从垂直居中 → 下移到聊天底部常规输入区位置（CSS transform/transition）
4. **角色带入**：角色选择 state 随消息传给 sendMessage（已有 `isDesigner` 传参通道）
5. **发送后**：角色选择消失，输入卡片变常规聊天页（消息列表 + 底部输入）

### 涉及文件
- `ProjectPage.tsx`（初始空态渲染）
- `ChatPanel.tsx`（空态 + 角色选择 + 下移动画）
- 新组件：输入卡片（角色胶囊 + 输入框）可复用

## 二、群聊彻底移除

### 现状
群聊模式：新建按钮「群聊会话」→ group-session 服务 → 多 Agent 协作。已无实际作用。

### 移除范围
- 新建按钮去「群聊会话」项
- `AgentTab` 群聊配置（Agent 模板 + 群聊配置）
- `settings-store` 的 group 字段（groupForwardStrategy / groupInjectMode / groupPresets）
- `group-session.ts` 服务 + `groupSystemPrompt` 相关
- 相关 IPC（group:*）

### 涉及文件
- `SessionBar.tsx` / `Sidebar.tsx` / `ProjectPage.tsx`（新建按钮）
- `settings/AgentTab.tsx`（群聊配置）
- `stores/settings-store.ts`（group 字段）
- `main/services/group-session.ts`（服务）
- `ipc-handlers.ts`（group:* IPC）

## 三、与既有改动的关系

- 角色选择实现（chatRole → isDesigner → MINT_DESIGN_BOOST）已就绪，本方案把它的 UI 从 ChatPanel 空状态升级为独立输入卡片
- 委派决策树改造（上下文保护）已就绪，与输入卡片无冲突
- 移除群聊与「多模型多Agent群聊方案」（docs/design/）冲突——该方案文档标注废弃

# 创建项目流程优化方案（讨论稿）

> **状态：📝 讨论中，未定稿**——2026-08-09 起讨论，内容为完整讨论记录（问题、分析、方案、参考、待决项）。
> 背景：EM v0.7.0 后回头审视创建项目流程（表单 → 初始化 → 方案 → 开发），发现多处与"AI 时代傻瓜式"不符的设计。

---

## 一、用户观察到的核心问题

1. **方案搜索不够深度**：Mint 推荐方案时对现实热门方案掌握不足——例如 AI 生图方案，现实大多数人选 doubao_seed / qwen 系列，Mint 却推荐 glm，与现实认知有差距
2. **能力边界不清**：deepseek 没有生图能力，但 Mint 把"生成图片"写进方案里——方案承诺了自身做不到的事
3. **用户不懂技术差异**：用户可能不懂框架、UI 风格、技术方案、AI 功能的区别，也不知道是否需要花钱
4. **费用陷阱**：用户选了"免费方案"，结果要配置 API key、要花钱——产生怀疑和不满（"说好的免费呢"）
5. **成品 UI 土气**：Mint 完成的 UI 往往过时土气，用户自己不懂设计、说不清想要什么，开发完很失望
6. **功能未经检验**：Mint 给出的功能列表看着没问题，但没经过原型检验，最后不满意
7. **认知差距**：很多人对"一个项目从产生想法到落地"的过程缺乏了解，不能把所有人当一样的对待——场景应分类（个人/企业、个人使用/多人使用、工具类/服务类、商用/开源、兴趣练习/验证想法/明确目标）

## 二、问题本质分析

| 现象 | 本质 |
|------|------|
| 推荐 glm 而非 doubao/qwen | **知识滞后**——模型训练数据有截止，热门方案热度是动态的，靠记忆必出错 |
| 选了免费方案却要配 API key 花钱 | **费用不透明**——"免费"定义模糊，成本没前置 |
| 不懂框架/技术方案区别 | **决策负担错位**——用户不该做技术选择，却被迫面对 |
| 成品 UI 土气、说不清想要什么 | **缺原型环节**——UI 质量靠 Builder 自由发挥，风格没先可视化 |
| 功能列表看着行、成品不满意 | **功能没验证**——文字列表 ≠ 用户理解，没经过"看见"这一步 |

## 三、五对策（初步方案）

### ① 实时检索替代记忆（解决知识滞后）
- 方案选型涉及**热门第三方服务**（AI 模型/云服务/地图/支付等）时，**强制先用 web_fetch 检索**（"XX 生图 API 对比 2026"、"XX 云服务价格"），热度、费用、维护状态以**检索结果为准**，禁止凭训练记忆推荐
- 兜底表述："若无法检索到可靠信息，明确告知用户信息不足，建议用户补充或选保守方案"

### ② 费用画像前置（解决免费陷阱）
- 推荐方案时**每个方案附带成本标注**：`免费（本地）` / `免费额度（XX 服务，超出付费）` / `需 API key（XX，约 ¥X/千次）` / `付费订阅`
- 用户确认方案时**成本已明示**，事后不再怀疑

### ③ 代选不抛题（解决决策负担）
- 技术选型 Mint 直接定 + 一句人话理由（"用 Vue 因为你要做后台管理，Vue 生态最顺"）——**不列对比表让用户选**（除非用户主动要求对比）

### ④ 原型必经流程（解决 UI 土气 + 功能验证）——最关键
- 流程改为：`需求文档 → 原型设计（Mint-D + 品牌库 + HTML 编辑器）→ 用户看原型确认 → task.json 开发`
- **能力全有**（Mint-D 设计师、74 品牌库、show_prototype、em-html-editor）——只是流程没强制
- 用户看原型：① 直观确认风格（不土气）② 点击原型检验功能（列表验证问题解决）
- 中等及以上项目**必经原型**；极简项目可跳过
- **连锁影响**：原型必经 → 任务顺序变化（先 UI 后逻辑）→ task.json 首任务变成"按原型实现 UI"——需一并设计

### ⑤ 风格大白话引导（解决说不清）
- 原型阶段用**白话风格选项**引导：`现代简约`（白底卡片）/ `活力彩色`（鲜艳渐变）/ `商务专业`（深色克制）/ `科技感`（暗色光效）——配品牌库参考图
- 用户选风格 ≠ 选技术，听得懂

## 四、场景分类模型（用户提出）

**主维度：项目目的**（决定流程深度，白话单选，用户听得懂）

| 目的 | 用户心智 | 流程深度 |
|------|---------|---------|
| **兴趣/练习** | "随便做做，学东西" | 轻流程：直接开发，快速出成果 |
| **验证想法** | "不知道行不行，先试试" | 原型优先：**先出可交互原型**，行再开发 |
| **实际使用** | "要真用，别糊弄" | 完整流程：需求→原型→架构→开发→测试→文档 |
| **商业交付** | "要做成产品/交付" | 完整 + 合规成本：授权、成本核算、部署、维护 |

**次维度**（补充细节，不改变主流程深度）：
- **使用范围**：自己用（本地数据）/ 小团队（简单账号）/ 公开（账号权限、数据隔离、部署）
- **形态**：工具（本地）/ 网站服务（部署）/ 移动应用（商店发布）
- **商业化**：免费开源（license、README 规范）/ 商用（定价、支付、合规）

**补充设计**：
- **流程地图透明化**：Mint 在项目开始时展示流程地图（"一个项目通常经历：需求 → 设计 → 开发 → 验证 → 发布。你的项目我们会走：①... ②... ③..."）——用户全程知道自己在哪一步、下一步是什么，消除未知恐惧（解决"不了解落地过程"）
- **原型 = 想法验证器**："验证想法"场景的最大价值：很多想法不需要开发就知道行不行——原型点一遍用户自己判断。验证流程：想法 → 原型 → 用户点击体验 → 决定（继续开发 / 调整 / 放弃）——**放弃也是成功**，省下开发成本
- **商用场景"丑话说前面"**：商业交付自动附加成本核算（API 费用/服务器/三方服务）、合规提示（隐私/支付/数据）、维护承诺说明

## 五、AI 时代交互方式（深层讨论）

### 核心判断：表单是"采集"思维，不是"共创"思维

- 表单假设**用户知道自己要什么**（只是没告诉我们）——但多数人只有模糊想法甚至没有想法
- 表单让用户"创作"（从零回答），而人最擅长的是"编辑"（对现成的东西做修改）

### 方向：对话共创 + 草案确认

1. **入口即对话**：点「新建项目」→ 直接进入与 Mint 的对话，开场只问一句白话："想做个什么？随便说，一句话也行"——一次只问一个，不轰炸
2. **草案先呈现**（比提问高效 10 倍）：用户说"我想做个宠物领养平台"→ Mint 不追问 20 个问题，先呈现草案：
   > "我理解你想要：① 发布宠物信息 ② 浏览/搜索 ③ 联系领养。类似项目核心就这三块。我建议先做个能用的简单版：发布页 + 列表页 + 详情页。界面风格可以选：温馨可爱 / 简约干净 / 活力明快 —— 你看这样对吗？"
   - **用户改草案比回答问卷容易**——确认/修改/否定，都是人最擅长的"编辑"
3. **灵感激发**（没想法的人）：用户说"不知道做什么"→ Mint 给灵感清单（产品方向而非技术选项）："很多人会做：记账工具、二手交易、兴趣社区、宠物助手、学习打卡……你想做哪类？"——选择比创造容易
4. **渐进披露**（30 秒起步）：第一轮只确认"做什么"；草案确认后再问"给谁用/要不要发布/是否商用"（场景维度）——每步都是对话，用户随时能说"不知道，你定"
5. **表单降级为补充页**：现有 5 步表单不删，变成草案确认后的可选补充（Mint 已代填，用户只改不填）；技术偏好彻底隐藏（Mint 代选 + 一句人话理由）

### 设计原则（判断标准）

| 原则 | 含义 |
|------|------|
| 一次一问 | 任何时刻用户只需回答一个问题 |
| 先给草案再问 | 永远先呈现"我理解的"，让用户改 |
| 白话 + 示例 | "后台管理界面（像淘宝卖家后台）"而非"管理后台 Web 应用" |
| 不知道就代选 | "不清楚就跳过，我按最稳妥的来" |
| 可随时反悔 | 每个阶段能说"换一个方向" |

## 六、参考搜集（开源/同类产品）

### 参考一：superpowers `brainstorming` skill（从想法到设计的黄金流程）

| 方法论 | 核心做法 | 对应 EM 痛点 |
|--------|---------|-------------|
| 一次一问 | 每轮只问一个问题，多选优先 | 表单轰炸 → 渐进引导 |
| 范围评估先行 | 多子系统先分解，不问细节 | 用户想法大而空 → 先切块 |
| 2-3 方案 + 推荐 | 先给推荐再解释，不抛选择题 | 技术选型负担 → Mint 代选 |
| 分节呈现设计 | 每节呈现后确认"这样对吗" | 功能列表不检验 → 分段确认 |
| HARD-GATE | 设计未批准前禁止实现 | 功能没验证就开发 → 原型门槛 |
| 设计落盘 | specs/YYYY-MM-DD-<topic>-design.md | 方案文档规范（EM 已有类似） |
| 终态 = 计划 | brainstorming → writing-plans → 实现 | 需求 → 架构 → task.json 的衔接 |

完整流程（brainstorming SKILL.md）：探索项目上下文 → 澄清问题（一次一问）→ 2-3 方案+推荐 → 分节呈现设计逐节确认 → 写设计文档 → 自查 → 用户审阅 → 进入计划。HARD-GATE：未呈现设计并获得批准前禁止任何实现动作（适用于所有项目，包括"简单"项目）。

### 参考二：Proma（同赛道产品，Claude+Pi 双引擎）

- **User profile schema**：简短用户画像（职业/正在做的事/水平/交互偏好/必须记住的，几百字）——不是表单，是画像——Agent 借助画像做回复偏好推理（Proma 2026 Q2-Q3 思考）
- **Proma Coach skill**：内置 skill 引导用户/Agent 把流程化内容沉淀为文档和 Skills——严肃工作流该记住的东西靠 Coach 引导存文档，而非模糊记忆
- **计划确认和用户追问**：Agent 模式内置"计划确认 + 追问"（EM 确认开发/原型确认已有雏形）
- **mailbox + Todo/看板**：任务分类、上下文关联、人类授权、可见性（EM 任务面板/确认开发可借鉴"人类确认"设计）
- **个人注意力**：人类并行操作 Agent 上限约 3 个，需上下文切换支持

## 七、综合提炼（改造方向）

```
新建项目 → 对话引导（superpowers 式）：
  ① 一次一问：先问"想做个什么"（多选+开放）
  ② 范围评估：想法太大 → 先切 MVP 块
  ③ 画像沉淀（Proma 式）：职业/用途/给谁用/预算——Mint 边聊边建 profile，不显式提问
  ④ 方案 2-3 + 推荐：技术选型 Mint 定，用户只确认
  ⑤ 原型呈现（分节确认 + HARD-GATE）：Mint-D 出原型 → 用户点 → 确认后开
  ⑥ 落盘：项目档案（profile + 决策记录）→ task.json
```

**核心转变**：从"表单采集" → "对话引导 + 画像沉淀 + 原型确认"——用户全程只说人话、做选择，Mint 负责专业部分。

## 八、待决项（后续讨论）

1. **场景入口**：表单第一步改"项目目的"单选（结构化）？还是进项目后 Mint 对话引导（自然语言）？——倾向**表单单选 + 动态显隐**（用户有掌控感，Mint 少猜）
2. **验证场景的原型**：用现有 Mint-D + HTML 编辑器流程，还是要更强的可交互点击原型工具
3. **流程地图**：放初始化时 Mint 主动展示，还是表单里展示
4. **极简用户 vs 深度用户**：同一入口还是分开（一句话要结果的 vs 想要完整规划的）
5. **具体对话流设计**：Mint 每轮说什么（细化对话剧本）
6. **原型必经的连锁调整**：task.json 首任务 = "按原型实现 UI"的流程设计

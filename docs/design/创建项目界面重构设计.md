# 创建项目界面重构设计（定稿 v2）

> **状态：定稿**——2026-08-10 修订。配套 `创建项目对话引导设计.md`（提示词 `<creation_flow>` 已实现）。
> **v2 变更**：明确「表单 vs 对话」分工边界（表单采结构化、对话采开放），新增全局「直接创建」按钮（Mint 感知采集进度）。

---

## 一、核心架构：表单与对话的分工

**原则**（用户决策 3）：表单负责采集**能具体量化或有固定选择的信息**；需要与用户讨论的内容（功能细节、UI、原型）放到提示词流程，两者互补配合。

| 信息类型 | 采集方 | 具体内容 | 特征 |
|---------|--------|---------|------|
| **结构化信息**（固定选项/可量化） | **表单** | 项目名、目录、平台（Web/小程序/桌面/CLI）、部署（自己用/放网上/都要）、AI 集成（不要/要问答/要自动）、完成度（完整/MVP/演示）、预算（充足/少量/免费） | 有标准答案，小白点选即可 |
| **开放信息**（需讨论） | **对话（Mint）** | 功能细节、UI 风格偏好、界面布局、原型实现与确认、技术方案取舍 | 没有标准答案，需边聊边定 |

**关键**：表单只问"有标准答案的"（选择题），对话聊"没有标准答案的"（开放题）。Mint 在对话中**不重复采集表单已采集的结构化信息**（除非用户要改）。

## 二、两个入口 + 全局「直接创建」按钮

### 入口 1：新建项目对话框（表单，保留）

- 侧边栏「+」→「新建项目」→ 打开现有 `NewProjectDialog`
- 职责：采集**结构化信息**（表单字段白话化 + 可跳过 + Mint 预填，见第三节）
- 创建后：Mint 拿到结构化信息 → 进入对话补**开放信息**（功能/UI/原型）

### 入口 2：全局「直接创建」按钮（新增）

- **侧边栏常驻**，任何页面/任何项目状态下可点（不局限于新建项目对话框）
- 点击 → 轻量输入：项目名（必填）+ 一句话想法（可繁可简，可空）
- 确定 → 创建项目 → 发系统消息给 Mint → 进入项目会话

**Mint 感知采集进度**（用户决策 2）：
- 系统消息携带"当前已采集的结构化信息快照"（若用户在表单里填过，带上；没填则空）
- Mint 据此判断：还缺哪些结构化信息、哪些开放信息 → 按 `<creation_flow>` 引导补全
- 举例：用户在表单填了"平台=Web、部署=放网上"，点直接创建 → Mint 知道已采集这些，只补"功能细节 + UI + 原型"；用户什么都没填 → Mint 从头引导

## 三、完整用户流程

```
用户想创建项目：
  ├─ 路径 A（完整表单）：新建项目对话框 → 填结构化信息 → 创建 → Mint 拿结构化 → 对话补开放信息
  ├─ 路径 B（直接创建）：点全局按钮 → 项目名+一句话 → Mint 从头引导（结构化+开放都对话里补）
  └─ 混合：表单填一半 → 点直接创建 → Mint 感知已采集进度 → 补剩下的
```

## 四、路径 A：完整表单体验优化（不砍字段，重做体验）

### 4.1 字段白话化（破认知痛）

| 现有字段 | 白话改造 |
|---------|---------|
| 部署平台（云端/本地/混合） | **"软件给谁用"**：只自己电脑 / 放网上给别人用 / 两者都要 |
| AI 集成（无/AI辅助/Agent/多Agent） | **"要不要 AI 能力"**：不要 / 要（帮用户问答）/ 要（AI 自动干活） |
| 完成度（完整版/MVP/演示版） | **"先做到什么程度"**：完整可用 / 先做个能跑的简版 / 先看个样子 |
| 目标用户 | 加示例："比如：我本人、我的家人、我的客户" |
| 技术栈（React/Vue/Svelte…） | **默认隐藏**，Mint 代选；点「高级」展开 |

### 4.2 可跳过 + 合理默认（破决策痛）

- 除「项目名」外全部可跳过，标注"可不填，AI 帮你定"
- 跳过的字段由 Mint 初始化时给默认值（`detectProfile`/`composeProfile` 已支持）

### 4.3 Mint 预填按钮（保持点击，用户决策 3）

- 现有「AI 推荐功能/技术」按钮保留强化：点一次 Mint 填全该步能填的字段
- 预填后用户只微调，不重写；**不做实时边填边预填**

### 4.4 费用前置提示（破预期痛）

- AI 功能等花钱项旁标成本："AI 对话需接 API 按量计费，轻量每月几块钱起；部分厂商有免费额度（有时效）"

### 4.5 示例 + 流程地图（破表达痛/动力痛）

- 关键字段旁给示例："别人通常这样描述：我想做记录每天花销的记账软件，给自己用"
- 表单顶部流程地图（简版）："填完 → 需求确认 → 界面原型 → 开发 → 完成"

## 五、路径 B：全局「直接创建」按钮

### UI 形态

- 侧边栏底部或顶部「+」下拉中，与「新建项目」并列的「直接创建」项
- 点击 → 轻量弹层（非 4 步表单）：项目名输入 + 一句话想法 textarea + 「直接创建」按钮

### 触发（系统消息）

```
用户点击直接创建项目，根据内置流程询问并引导用户继续。
项目名：XX。用户想法：XX。已采集信息：<结构化快照或"无">。
```

- 目录名：翻译英文名，保持现有 `buildDirectoryTranslationPrompt` 逻辑（用户决策 1）
- 进入项目会话后，Mint 按 `<creation_flow>` 引导，跳过已采集的结构化信息

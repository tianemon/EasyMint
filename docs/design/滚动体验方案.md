# 聊天滚动体验方案（微信式）

> 2026-08-07 定稿。解决：首次打开不贴底（老问题反复）+ 流式不锁定（已有）+ 新消息气泡提醒（新增）。

## 需求

1. **首次打开页面**（应用启动/进入会话，不含窗口切回）：自动定位底部，显示最新消息
2. **流式输出不锁定**：可随意翻看上方消息（用户滚动即解锁）
3. **离开底部 + 有新消息**：底部弹气泡提醒（微信风格），点击回底部
4. 整体参考微信等成熟聊天工具

## 现状分析（ChatPanel.tsx）

| 机制 | 现状 | 问题 |
|---|---|---|
| `autoScrollRef` | 用户滚离底部(>8px) → false 停止跟随；滚回 → true | 保留 |
| `handleScroll` | 用户滚动判定 | 保留 |
| `scrollToBottom(force)` | force 或 autoScrollRef 时贴底 + 80ms 防抖兜底 | 保留 |
| 打开会话贴底 | `prevMsgCountRef` 0→N 时 `virtualizer.scrollToIndex(last)` | **prevMsgCountRef 会话切换不重置**——切 tab/开新会话后 0→N 不触发 → 不贴底 |
| 流式跟随 | onStream 每帧 scrollToBottom() | 保留 |

**"不会自动定位到底部"根因**：`prevMsgCountRef` 是组件级 ref，会话切换（tab 切换/新会话）后保留旧值，`messages.length>0 && prev===0` 条件不再满足 → 打开会话的 scrollToIndex 贴底不触发；且 autoScrollRef 可能被上一次会话的滚动状态污染（false）。

## 方案

### 1. 会话切换重置（首次打开贴底可靠化）

`useEffect([sid])` 重置：
- `prevMsgCountRef.current = 0`（重新触发 0→N 贴底）
- `autoScrollRef.current = true`（恢复跟随，防上次会话的 false 污染）
- `setShowNewMsg(false)`（清气泡）

贴底双保险：0→N 时 `virtualizer.scrollToIndex` + `scrollToBottom(true)`（80ms 防抖兜底）。

### 2. 新消息气泡（新增）

- **state**：`showNewMsg: boolean`
- **触发时机（用户定稿）**：**回合完全输出结束（busy true→false）**才提示——流式过程中不提示（不打扰翻阅）；结束时若 `autoScrollRef.current === false`（用户不在底部）且本轮有新内容 → `setShowNewMsg(true)`
- **"本轮有新内容"**：onStream 内容帧更新时置 `streamHadContentRef = true`；busy 结束时读取并重置
- **隐藏**：
  - 用户滚回底部（handleScroll 中 `distFromBottom < 8` → autoScrollRef=true）→ 隐藏
  - 点击气泡 → `scrollToBottom(true)` + autoScrollRef=true + 隐藏
- **UI**：消息列表容器底部居中胶囊按钮（absolute 定位），文案「最新消息」+ 下箭头（SVG）；点击事件
- **样式**：`index.css` 新增 `.new-msg-bubble`（浮起层、投影、hover 态，颜色走语义层）

### 3. 流式不锁定

保留现有 autoScrollRef/handleScroll 机制（用户滚离底部即解锁，onStream 不再拉回）。

## 实施记录（2026-08-07，多轮迭代后定稿）

### 探索过程（死胡同记录，避免重走）

1. **手写 scrollTop = scrollHeight**：虚拟化 totalSize 是估算混合 → 贴底不准；且贴底后测量增长触发 scroll 事件 → handleScroll 误判 autoScroll=false → 停止跟随。加"300ms 保护窗口"缓解 → 测量持续 >300ms 时仍误判（此消彼长）
2. **anchorTo: "end" + scrollToIndex（库官方）**：读源码确认库机制——但 `wasAtEnd` 用 totalSize-based 距离判定，与 DOM 实际高度有偏差（估算混合），贴底后内容增长时判定失效（实测 dist 0→125）；`scrollToIndex` 的 scrollState 校正只补偿"视口上方"的项，底部项测量不触发
3. **等测量收敛（interval 500ms 无变化）**：巨型消息测量持续数秒/抖动 → 窗口永远等不到
4. **固定多点贴底**：不精确且反复

### 最终方案（v2，用户确认有效）

**核心突破：用户意图用 wheel 输入判定，scroll 事件只做恢复判定**——程序性贴底/测量增长产生的 scroll 事件永不取消跟随（误判彻底消除）：

| 事件 | 判定 | 效果 |
|---|---|---|
| wheel 向上滚且 dist>8 | 用户翻阅历史 | autoScrollRef=false（唯一取消路径） |
| scroll 事件 dist<8 | 滚回底部 | 恢复跟随 + 隐藏气泡 |
| totalSize 变化（流式/测量推进） | autoScrollRef=true | scrollToIndex(last, end) 贴底 |
| 打开会话（0→N） | scrollEl 就绪后 | 贴底一次，测量推进由 totalSize effect 跟进 |

**其他要点**：
- `scrollToBottom`：从 store getState 读最新消息数 + rAF 延迟（事件处理中 virtualizer count 未更新，scrollToIndex 会 clamp 到旧最后一条——发送消息不显示自己消息的根因）
- anchorTo: "end" 保留（followOnAppend：count 变化且用户在底部时自动贴底）
- 气泡：busy 结束（输出完）+ autoScrollRef=false + 本轮有内容 → 显示；点击/滚回底部消失

## 验证

1. 应用启动打开历史会话 → 贴底显示最新消息
2. tab 切换/新建会话 → 贴底（原 bug 场景）
3. 流式输出中滚动查看上方 → 不锁定；底部有新内容 → 气泡出现
4. 点击气泡 → 回底部 + 气泡消失；滚回底部 → 气泡消失
5. 窗口切回（非首次）→ 不强制贴底（保持当前滚动位置）

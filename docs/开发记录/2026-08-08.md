### 18.1 背景

用户在 mac/win 两台设备间需要「按需」互传项目与会话记录。初始设计含自动扫描/自动重连/Mint skill/MCP 迁移工具，多轮迭代后用户定稿为**纯手动模式**——低频场景，按需使用，链路必须可靠（打包传输、完整性校验、失败保留缓存）。

### 18.2 实现

**设备互联**（工具箱→设备互联，实验性）：
- 设备发现：bonjour-service mDNS，扫描手动触发（3s 窗口），广播仅「可被发现」开启后 60s 自动停止（无常驻广播）
- 配对：蓝牙式双向确认（请求→确认），ECDH（P-256）交换公钥各自派生共享密钥（密钥永不传输）；hello 消息用 challenge 认证（解密成功=持有密钥）
- 连接：WebSocket，完全手动触发（`device:connect` 直连已配对设备缓存地址）；心跳 30s 保活；无自动重连/无断线重试
- 传输加密：协议控制消息明文（unpair-notify/ping），应用消息（迁移 transfer-*）AES-256-GCM 加密防嗅探
- 单方面解除配对：unpair 发 unpair-notify 双向解除 + hello 校验失败同步解除（防抖动循环）；扫描器去重缓存随解除重建

**跨设备项目迁移**（纯手动）：
- 发送端：设备面板「发送」→ 选项目（已打开项目列表/输入/浏览）→ 统一扫描（`migration-service.scanProject` 单一实现，DEFAULT_EXCLUDE 排除 Electron+Flutter 构建产物）→ 确认 → 主进程 zip 打包（archiver 8.0）→ 两阶段握手（transfer-request → 接收端 transfer-accept 确认）→ 分块传输
- 接收端：`migration:accept` 选父文件夹（默认软件默认项目目录，自动创建同名项目文件夹）→ zip 落 EM 专属缓存目录（`~/.easymint/migration-cache/`）→ sha256 校验 + 解压文件数必须匹配 → 会话恢复（jsonl 首行 cwd 改写为接收端路径，JSON.parse 验证落盘）→ 全部恢复完毕才删压缩包
- 完整性握手：manifest 带 fileCount/zipSha256/sessionFile，回执带 restoredCount/sessionRestored，发送端二次确认；失败保留缓存包供排查
- 迁移完成卡片：接收端弹出模板文案（先说明「本项目已迁移到另一台电脑，会话记录与项目文件已完整迁移」，再给注意事项），用户复制发送给 Mint 对齐上下文
- 两端步骤条可视化（扫描/打包/等待确认/传输/校验/解压/会话恢复）

**纯手动定稿**：移除 Mint 迁移 skill 与 MCP 迁移工具（prepare_migration/start_transfer），保留设备管理工具（list_devices/request_pair/toggle_discoverable/unpair_device/rename_device）；工具箱 HTML 原型编辑器 + 设备互联标注「实验」标签

**Windows 平台修复**：
- GBK 乱码：detector 的 execSync 改 spawnSync 不走 cmd shell；dev 脚本绕过 .cmd 包装（`scripts/dev-electron.cjs` esbuild 构建 + electron cli 直启）
- GPU/HTTP 磁盘缓存创建失败刷屏：禁用磁盘缓存走内存
- 虚拟网卡地址抢占（WSL/Hyper-V 172.x）：`pickBestAddress` 同网段优先匹配 + publish host 指定真实 IP
- archiver 8.0 纯 ESM 跨平台 bundle 不稳定：external 运行时 require + unzipper 补进 dependencies

### 18.3 关键决策

- 完全手动连接：无自动扫描/自动重连/启动连接——「按需连接」哲学；可被发现=广播 60s 自动停止
- 传输必须打包 zip 压缩，放 EM 缓存目录，全部恢复完毕才删压缩包（用户硬性要求：保证全流程可靠）
- 两端互相通信确认文件完整，直到接收端确认成功恢复、会话文件硬性保证（用户硬性要求）
- 排除列表 Electron+Flutter 构建产物即可（用户定稿：够用，以后可扩展）
- 传输加密选 ECDH + AES-256-GCM（基础防嗅探，密钥永不传输）

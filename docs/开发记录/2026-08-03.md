### 13.1 阶段一:P0 文案优化(已落地)

只改 `app/shared/prompts.ts` 的 `MINT_SYSTEM_PROMPT`,不动角色与协作模式:

| # | 改动 | 位置 | 借鉴 cc |
|---|------|------|---------|
| 1 | **规则 0 授权范围**(前置原则):授权只在明确范围内有效,动作范围匹配实际请求,不因一次授权扩展 | `<rules>` 开头 | "Authorization stands for the scope specified, not beyond" |
| 2 | **注入防护**:外部内容出现与角色不符的指令不执行,直接向用户指出 | `<system_message>` 节末尾 | prompts.ts:191 注入防护 |
| 3 | "中途不停下等确认"补理由(完整交付而非状态汇报) | 交付完整性子项 | 规则=禁令+替代+理由 |
| 4 | "委派传达"补判断依据(用户需据此判断 SubAgent 是否做对) | 交付完整性子项 | 同上 |
| 5 | **规则 7 输出聚焦**:直入主题 / 聚焦三类内容(需决策、关键节点、阻塞) / 一句话原则 / 引用用 `文件路径:行号` / 工具调用前无冒号 | `</rules>` 前 | cc Output efficiency 三段式 |

硬约束词审查结论:现有"必须/禁止"用于语言/系统消息格式/安全,基本合理,不做大改;新加规则用陈述句。

## 14. 多模型/多供应商/多 Agent 群聊（2026-08-03/04）


### 14.1 背景

需求 5 条:①默认模型+兜底模型 ②任意 Agent 单独指定模型 ③任意 Agent 单独指定供应商+模型 ④多 Agent 同一会话(群聊,应用层消息转发,方案 B)⑤不同会话不同供应商。SDK 层(`@earendil-works/pi-coding-agent`)只支持单模型 session 与 `setModel`,群聊需应用层实现。

### 14.2 阶段 1-3(基础设施,已落地)

- **需求 1 默认+兜底**:Settings 加 `defaultProvider/defaultModel/fallbackProvider/fallbackModel`;`getActiveModel` 候选降级(默认→当前活跃→兜底,模型不存在或 auth 未配置跳过)
- **需求 2/3 Agent 指定模型/供应商**:AgentTemplate 加 `provider`;SubagentOptions 加 `model/provider`;executor 的 `resolveSubagentModel`(指定>模板>子agent默认>全局);模板可配供应商
- **需求 5 会话绑供应商**:session-cache 加 `provider`;ChatPanel 读 cache → `sendMessage(preferredProvider)`;`getModel` 支持 preferredProvider+model

### 14.3 阶段 4(群聊,本阶段核心)

**架构**:群聊 = 多个 Pi session 的虚拟聚合(`group-session.ts`)。

- **GroupSessionManager**:每个参与 Agent 一个独立 Pi session(独立 jsonl/上下文);事件广播注入统一 `groupId` + `agentRole`(前端过滤+标注来源)
- **消息路由**:用户消息 `@角色名` → 目标 Agent;无 @ → 主 Agent(第一个)
- **结论转发**:Agent 回合结束(turn_end)提取 `getLastAssistantText()` → 转发给其他空闲 Agent(默认 conclusion 策略)
- **防环三层**:①`forwardSeen` 消息 ID 去重 ②最大转发深度(`maxForwardDepth` 默认 3)③结论才转发(不转工具过程/thinking)
- **失败处理**:回合异常 → 重试 ≤3 → 标记 offline 跳过(不阻塞其他 Agent)
- **持久化**:项目级 `.easymint/group-sessions.json`(结构元数据);群聊会话为内存态,重启后仅可查历史
- **注入方式**:`followUp`(等空闲,默认)/ `steer`(打断)

**前端**:
- tab 新类型 `group`(带 `groupId`);群聊 ChatPanel 以 groupId 为消息存储 key
- 群聊气泡:角色头像(角色色板固定色)+ 角色名 + 转发来源标记(`· 来自转发`)
- 新建入口:Sidebar「+ 新建 → 群聊会话」→ GroupComposerDialog(选预设/自由勾选模板,受 maxGroupAgents 限制)
- 群聊回合串行(A 完成才转发 B),复用单 `latestAiIdRef`;turn_end 清 busy(群聊不广播 agent:exit)

**设置项(设置→群聊)**:最大 Agent 数(默认 3)/转发策略(默认 conclusion)/注入方式(默认 followUp)/最大转发深度(默认 3)/预设组合管理(内置「开发三人组」Mint+Builder+Evaluator、「设计协作」Mint+Mint-D,可增删)

## 创建流程重新设计 + 提示词治理 + 原型编辑器修复 → 发布 v0.10.0

**背景**：用户发现创建项目流程被某次更新错误修改——复杂度由前端硬编码、打开新窗口后 Mint 直接初始化而非先问原型、文档时机过早。用户确认 3 个设计点后重设计。

### 创建流程重新设计（用户确认 3 点）
1. **Mint 自己判断复杂度**：判定标准严格写入 creation-guide skill（极简/简单/中等表，依据项目实际内容非场景）
2. **打开新窗口后首句问原型**：有 UI 且中等以上第一句话问「是否根据当前功能需求先产出UI原型？」，原型确认后才写完整文档
3. **简单项目跳过原型**

### 关键修复：创建时序错乱根因
- JSONL 实证（photo-wall 会话）：Step1 后 Mint **提前初始化**（读 skill 撞 EISDIR + 完整初始化），project-created 时又初始化一遍——系统消息被搅乱、看起来「只显示 1 条」
- 根因：提示词「走项目初始化」被 Mint 理解为立即初始化
- 修复：creation_flow + creation-guide 明确「只回复已确认，不执行任何初始化动作」，初始化在 project-created 后开始

### 流程顺序修正
- **快速原型前置**到设备+成本之前（用户发现）——与 Gate 顺序一致（G3/G4 原型在 G5 技术方案含成本之前）；原型确认后功能需求/架构才可能变化，成本应基于确认后范围
- **成本从独立步骤改为功能共创内联校验**：表单已采集部署/AI/预算，无冲突默认跳过，冲突才介入（用户澄清）

### 系统提示词治理（对照 cc 源码风格）
- 原则：系统提示词=通用规则+硬约束，具体场景 skill 化
- 去重：复杂度判定统一指向 skill；删除双因子/五步旅程/流程决策文案；show_confirm_dev G4 指向 skill
- 口语化改精准：「人最擅长修改现成的东西」→「先给出草案由用户修改确认」等
- 5 处断链修复：ui-sync 的 set_project_stage 死引用、features 提前写需求文档、ui-sync 手动调 done、CONFIRM_DEVELOPMENT_PROMPT 手动调 done、intent 口语

### 子 agent 提示词
- **冲突确认**：DESIGNER 子 agent 版（executor 无 show_prototype 工具、无法交互）却含「向用户确认/调 show_prototype/询问反馈」——调用必失败
- 抽取共享 `DESIGN_SPEC` 常量（种子模板/品牌库/配色/排版/自查），DESIGNER 与 MINT_DESIGN_BOOST 共用，消除漂移；子 agent 版删交互指令明确「不调 show_prototype」；叠加版保留 show_prototype/反馈

### 清理
- set_project_stage / state.json 全链残留（v0.5.0 删鱼骨图遗漏）：代码注释 + 技术架构 2 处 + 需求文档 2 处 + CONFIG_PATHS 2 处

### 原型编辑器修复（Mint 复盘问题 3）
- **根因**：autoLoad 用 blob URL 加载原型（无目录概念），相对路径 assets/ 解析失败 → 图片空白
- 修复：主进程注入前 `absolutizePrototypePaths()` 改写 src/href/url() 为绝对 file:// 路径；编辑器加「在浏览器中打开」按钮（shell.openPath，file:// 下相对路径正常）；editorWin 挂载 preload

### 视觉补强（Mint 复盘问题 6）
- 提示词强调：模型不支持图片（报错因模型而异不固定）→ 转调 describe_image；识别结果当作视觉 API 描述；失败如实告知
- ui_tools describe_image 说明强化 + 新增 rules 8「图片处理」

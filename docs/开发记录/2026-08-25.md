## 08-25 深夜：后台 shell 无输出根因定位（Mint 命令自带重定向）

### 排查过程（修正前一版结论）

- 用户 dev 版实测：Mint 后台启动 → 输出面板"等待输出"、日志文件为空；运行面板启动 → 输出面板正常、不建日志文件
- 加诊断日志（start/spawned/data/flush）+ 纯 node 复现：spawn 配置（shell:true + detached:true）跑 flutter run 输出完全正常 → registry 链路本身无问题
- **真根因（用户日志揭示）**：Mint 生成的命令自带重定向——
  `cd ... && flutter run -d macos --debug > /tmp/macos_show2.log 2>&1`
  输出全被 shell 重定向走，registry 管道收不到 → 日志文件空 + 面板"等待输出"。`/tmp/macos_show2.log` 有 1514 字节完整输出佐证
- 已安装版 v0.11.0 的旧「空文件 + 无输出」现象同样由此解释（decodeSeg/缓冲修复都未触及这个场景）

### 修复（提示词引导，治本）

1. **系统提示词**（prompts.ts「长命令后台执行」）：明确后台命令输出自动收集（面板实时显示/落盘/退出注入），**禁止手动重定向**（> file 2>&1、| tee、nohup ... &）——重定向绕过自动收集；读完整输出用 read 读返回的日志路径
2. **增强 bash 工具**（tool.ts）：description / promptSnippet / promptGuidelines（追加）/ 返回文本同步上述约束
3. **面板兜底**（ShellProcessView）：运行中无内容时提示「若命令手动重定向了输出（如 > file 2>&1），此处不会显示」

### 保留的健壮性修复（防御性）

- decodeSeg 前缀即时输出（混非 UTF-8 字节不再卡输出）

### 验证状态

- lint 全通过；待用户 dev 版复现（Mint 后台跑 flutter run 应不再加重定向，面板有实时输出）

## 08-25 深夜补：EM 弹窗"跳过阈值"盲区——回合内上下文暴涨无上报

### 用户追问

设置了 75% 压缩阈值，第二次直接触发 SDK 自动压缩（98%），跳过了 75%——不合理。

### 根因（会话 jsonl 回合边界实证）

- 09:53:19 用户「你直接做」→ **单一长回合持续 14 分钟**（几十次工具调用，无中间用户消息）

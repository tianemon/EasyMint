# 开发记录 2026-08-10

## 20. Pi 配置目录体系统一 & Claude SDK 遗留清理（2026-08-10）

> 背景：EM 与 Claude Code 解耦后仍有隐式耦合未闭环——Pi SDK 默认读取项目的 AGENTS.md/CLAUDE.md 与 `.pi/` 资源；agentDir 双目录（`pi/` + `pi-agent/`）职责分裂；`~/.easymint/` 下积累大量 Claude SDK 时代遗留。

### 20.1 排查结论（源码实证）

- **Pi 默认目录体系**：全局 `~/.pi/agent`（可用 `PI_CODING_AGENT_DIR` env 或 `agentDir` 参数覆盖）+ 项目级 `<cwd>/.pi/`（CONFIG_DIR_NAME）+ 上下文文件 AGENTS.md/CLAUDE.md（agentDir + cwd 逐级向上扫描）
- **EM 映射方式**：env 指向 `~/.easymint/pi-agent`（ModelRuntime 用）+ 显式参数指向 `~/.easymint/pi`（resourceLoader 用）——两个"全局目录"并存
- **隐式耦合**：`noContextFiles` 未传 → 项目 CLAUDE.md/AGENTS.md 仍注入 Mint 系统提示词（EasyMint 项目自己的 CLAUDE.md 就是实证）；`noExtensions/noPromptTemplates/noThemes` 未传 → 项目 `.pi/` 资源会被加载（trusted 时）
- **遗留文件**：`~/.pi/agent/`（含旧 deepseek 配置）、`~/.easymint/settings.json`（含 deepseek API key，无代码引用）、`~/.easymint/.claude.json`（Claude 全局配置，含 userID/machineID）、`telemetry/`（32 个 Claude SDK 遥测事件）、`projects/`（Claude SDK 会话）、`commands.json`（Claude 命令迁移遗留，全 app 无引用）、147 个 `__new_` 孤儿临时文件（早期原子写残留）

### 20.2 用户决策

1. **`~/.easymint` 替换 `~/.pi` 层级**——不想要 `.easymint` 下再有 `pi/`、`pi-agent/` 子目录；严格对应 Pi 默认 `~/.pi/agent` 结构 → agentDir 统一为 **`~/.easymint/agent/`**
2. 清理清单（11 项 + 2 项二次筛选）全部确认后删除

| `app/main/services/agent-service.ts:392` | `getAgentDir()` → `~/.easymint/agent`（8 个调用方随动） |

**资源流向（改后）**：Mint 上下文 = 100% EM 自己组装（Mint 提示词 + EM skills + env/profile 动态 section），项目 CLAUDE.md 对 Mint 不再生效。

### 20.7 决策修正：保持 Pi SDK 默认行为（同日，v0.7.2 修正版）

> 20.1-20.6 中"资源发现全关（5 个 no\*）"的方向**修正**——用户澄清意图后撤销，保留原记录作为决策演变历史。

**用户意图澄清**（关键）：
- "解耦"指的是**去掉 Claude SDK 依赖及其产生的文件**（`~/.claude/.claude.json`、telemetry/、projects/ 会话等遗留）——这部分已完成
- **Pi 的行为不做任何限制**：Pi 本身读 CLAUDE.md、扫项目 `.pi/` 等都是 Pi 默认行为，保持 SDK 默认，EM 只在之上扩展
- 项目级 `.pi/` 无法指定为 `.easymint`（`CONFIG_DIR_NAME` 是 SDK 包级常量，读 SDK 自身 package.json 的 `piConfig.configDir`，无 env 覆盖）——实证：现有 6 个项目均无 `.pi/`，实际零影响
- settings.json 与 em-settings.json 职责分离不冲突（Pi 写 Pi 的，EM 写 EM 的）

**修正实现**：
1. `pi-session.ts` resourceLoader：**撤销全部 5 个 no\***（noSkills/noContextFiles/noExtensions/noPromptTemplates/noThemes），只留 `systemPromptOverride`——Pi 资源发现完全默认
2. `pi-init.ts`：settings 从 `SM.inMemory()` 单例 → **磁盘模式** `SM.create(cwd, agentDir)`（每会话新建，去单例——磁盘模式绑定 cwd，多项目不可复用；compaction 默认即 enabled 无需传）
3. 文档同步：CONFIG_PATHS 映射章节、CHANGELOG v0.7.2 条目重写

**修正后行为**：Mint 上下文 = Mint 提示词（systemPromptOverride）+ **Pi 默认注入（项目 CLAUDE.md/AGENTS.md、`.pi/` 资源、SYSTEM.md/APPEND_SYSTEM.md，trusted 时）** + EM 扩展层（skills + env/profile section）。项目 CLAUDE.md 重新生效（EM 模板自带的 CLAUDE.md 准则恢复可读）。

### 20.8 项目级目录定制 & 会话目录归默认（同日，v0.7.2 终版）

> 用户担忧：Pi TUI 与 EM 共享项目级 `.pi/settings.json`（compaction/theme 等字段）会互相冲突——EM 无法覆盖项目级 compaction（project 优先于 global），冲突真实存在。

**项目级 `.pi` 改得动**：`CONFIG_DIR_NAME` 虽无 env 覆盖，但 `piConfig.configDir` 是官方定制点（SDK 运行时读自身 package.json）——**EM 作为分发方，启动时幂等定制**本地安装的 SDK 包：

```typescript
// index.ts：app.getAppPath()/node_modules/@earendil-works/pi-coding-agent/package.json
// （打包后 .asar → .asar.unpacked；缺 configDir 才补写；npm install 覆盖后下次启动自动恢复）
```

已验证（本机）：patch 后 Pi 运行时 `CONFIG_DIR_NAME = ".easymint"`、默认 `getAgentDir() = ~/.easymint/agent`。

**效果**：Mint 项目级目录 = `<cwd>/.easymint/`（与 EM 的 state.json/run.json 共存）；**pi CLI/TUI 用独立全局 SDK → 仍 `.pi`**——彻底隔离。写失败（mac 签名权限）降级 `.pi`（功能不受影响，打日志）。

**会话目录归 Pi 默认**（用户决策 B）：`getPiSessionDir` 从 `~/.easymint/sessions/<编码>` 改为 `agentDir/sessions/<编码>`（= `~/.easymint/agent/sessions/`，9 个调用点经此函数自动跟随）；启动时一次性迁移旧目录（幂等，跨盘降级复制）；本机 6 个项目会话已手动迁移完成。

**当前终版结构**：
```
~/.easymint/
├── agent/                    ← agentDir（Pi 默认布局）
│   ├── auth.json / models-store.json / settings.json（Pi 磁盘模式）
│   └── sessions/<编码cwd>/   ← 会话（Pi 默认布局）
├── em-settings.json / mcp.json / skills/ ...（EM 自管）
└── <各项目>/.easymint/        ← 项目级（Pi 配置 + EM state/run/issues 共存）
```

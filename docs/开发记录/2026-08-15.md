### 委派子 Agent 过程弹层（SubagentProcessView，3 处修复）

- **message_start 消息边界**：实时路径此前只处理 message 帧（"末尾 streaming 替换"），忽略 message_start——子 agent 多输出段（思考→工具→文本）时后段覆盖前段内容（实时显示错误，靠 3s 重载才恢复）。修复：message_start 终态化当前 streaming 块 + 带 blocks 直接渲染新气泡，与主聊天 ChatPanel 每条独立气泡对齐
- **3s 重载兜底 key 冲突**：`d.startsWith(s)` 分支把磁盘消息标 streaming 作为流式块保留，下次重载新旧两批次磁盘消息共存 → React key `d-uuid-N` 重复（用户报错 `d-3900db8a-68`）。修复：streamBlock 只认实时块（keyId undefined），磁盘已含流式内容直接以磁盘为准
- **空白气泡**：纯思考/纯工具消息在开关关闭时气泡容器仍渲染（内容隐藏）→ 视觉空白气泡。修复：按开关过滤可见条目，无可视内容不渲染容器

### 状态栏信号语义精确化（ChatPanel）

- 调查确认：SDK `agent-loop.js` 源码——`turn_start` 在 API 请求发出前 emit，至 message_start（首个响应块）之间 SDK 无事件 = 等待 API 返回
- turn_start → "正在请求"（替代无条件"正在思考"）；thinking 块 → "正在思考"（严格绑定）；tool_done → "正在处理"（中性等待态）
- 状态栈机制（status-store 单 id request + 文本更新 + tool 信号回退）审查：修改与机制完全兼容，栈价值在 request↔tool 回退与多信号共存

### 角色选择器快速拖动回弹（滑块状态机）

- 用户报告：快速从一个选项拖到另一个选项松手太快 → 返回原选项；等 1s 再松手正常
- 诊断日志（down/up/nearest）证实落点计算全部正确 → 根因在 `onLostPointerCapture={abortDrag}`：pointerup 后浏览器自动释放 capture → lostpointercapture → abortDrag → syncSlider 读旧 chatRole（React 未 flush）→ setSliderBox 旧选项覆盖落点

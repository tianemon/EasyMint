### 输入卡片下移动画（FLIP 调试全程，重要教训）

**原实现**：0.3s 淡出 + 布局跳变 → 用户反馈"像重新加载"。

**尝试 View Transitions API（失败，放弃）**：
- 日志实证：Chrome 旧快照捕获在 updateCallback 完成之后 → 回调式更新新旧快照相同、无动画
- callback 内 rAF 冻结（transition 挂起期间渲染停止）→ updateCallback 超时中止（页面卡死数秒）
- 多 tab 共存时多个 .input-card → duplicate view-transition-name 错误
- 结论：Electron 43 上 startViewTransition 回调式更新不可行

**手动 FLIP 调试历程（5 轮）**：
1. 测容器位置 → 容器顶/底在 flex 布局中不变（flex-1 撑满→shrink-0 贴底，bottom 都是窗口底），dy 错 → 上跳
2. 改测卡片包裹层 + 轮询等 virtualizer 占位 → dy 正确（-297, frames=1）但反位移晚 1 帧（已绘制 672 才设）→ 抖动
3. useLayoutEffect 绘制前反位移（用户记录的"修好"方向）→ dy=0（virtualizer 未占位时实测 last 不准）→ 无动画
4. 回轮询 + 隐藏（opacity 0）方案 → 开始不闪但 fill:none 结束回退（日志实证 layoutTop=375）→ 结束抖动
5. **定稿**：目标位置预测（窗口高 - 卡片高 - 16px margin，卡片贴 ChatPanel 底部，不依赖 virtualizer）+ useLayoutEffect 绘制前反位移 + WAAPI `fill: forwards`（保持终点、onfinish 清理无跳变）→ 修复

**教训（用户指出）**：基于已验证节点增量修复（useLayoutEffect 方向对，只修 dy=0），不推倒重来；修复要组合完整机制（开始+结束防抖），不一次只修一个症状。

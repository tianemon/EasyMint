# 跨设备会话迁移与设备互联方案

> **状态：✅ 已实现（v0.6.6）**。唯一真相源。
> 需求来源：win 开发中项目（会话进行数天）→ 一次性迁移到 mac 继续开发（win 不能打 mac 包）；迁移通道同时为将来跨设备会话消息传递铺基础。

## 一、目标与边界

### 目标

1. **一次性会话迁移**：win 端项目会话 → 局域网传输 → mac 端放入本地对应位置 → 会话自动可见，点击即 resume 继续开发
2. **设备互联基础**：局域网内设备互相发现 + 配对 + 连接，此通道未来承载跨设备会话消息传递

### 明确不做（本阶段）

- 不做实时同步、增量同步、双向冲突合并——一次性的"导出→传输→导入"
- 不做跨公网（WebRTC/TURN/云中转）——仅局域网
- 不做瞬时状态同步（打开状态/正在构建等，各端自持）
- 项目代码同步继续走 git（已有局域网 bare 仓库方案）

### 关键事实（EM 会话存储机制，来自 CONFIG_PATHS.md、pi-session.ts 与 win 真实数据验证）

- 会话目录：`~/.easymint/sessions/<路径编码>/`，编码 = `cwd.replace(/[:/\\]/g, "-")`
  - win：`C:\Users\81197\EasyMintProject\lan-notes` → `-C--Users-81197-EasyMintProject-lan-notes`
  - mac：`/Users/amon/dev/project/xxx` → `-Users-amon-dev-project-xxx`
- 会话文件：`<时间戳>_<sessionId>.jsonl`，**首行 session 条目含 cwd（原始绝对路径）**——SDK resume 时从文件 header 自动读 cwd（`SM.open` 只传文件路径）
- **路径身份差异 = 迁移核心难点**：导入必须 ①放入 mac 编码目录 ②改写首行 cwd 为 mac 路径，否则不可见/恢复找错项目
- **迁移粒度（用户定稿 2026-08-08）**：**只迁最新主会话 jsonl 一个文件**；`<sessionId>/subagents/` 子 Agent 会话执行完即无用，不迁（真实数据验证：主会话 jsonl 内对子会话文件引用 = 0，无悬空）
- 需要改写的路径字段：**仅首行 session 条目的 cwd 一个字段**（真实数据验证：agentDir/sessionDir/path 均为 null）；主会话 + 每个子会话 jsonl 首行都有 cwd，但只迁主会话 → 只改 1 个文件
- 会话内工具调用的历史绝对路径（win，真实数据 60+ 处）**不改写**——仅历史展示，不影响 resume；重新执行时 AI 按新路径重读

## 二、设备互联设计（对齐蓝牙/WiFi 连接模式）

> 核心原则：**交互流程与状态机完全照搬蓝牙/WiFi 成熟模式，不自行创造**。
> 蓝牙配对后广播/扫描全部停止、只维持连接——这是"不要无脑频繁扫描"的天然答案。

### 概念映射

| 蓝牙/WiFi | EM |
|-----------|-----|
| 广播（advertisement） | mDNS 周期通告（设备名/UUID） |
| 扫描（scan） | 监听局域网通告 |
| 配对（pairing/PIN） | 首次双向确认 + 密钥交换 |
| 连接（GATT/WiFi 数据连接） | WebSocket 长连接 |
| 已配对设备列表 | 持久化配对记录（密钥/设备 UUID） |
| WiFi 记住网络自动连 | 启动时自动连接已配对在线设备 |

### 发现状态机

```
状态1: 未开启发现(默认静默)
       不广播、不扫描——完全隐身(对齐蓝牙默认不可发现)
   ▼ 用户开启"可被发现"开关(或进入配对页)
状态2: 配对模式(最长 5 分钟自动退出)
       广播: 每 2s 通告一次(蓝牙 <2.5s 可靠发现阈值)
       扫描: 持续监听(桌面局域网不耗电,无需移动端占空比限制)
       → 发现设备 → 点选 → 对方弹确认 → 交换密钥 → 配对成功
       → 5 分钟无新配对 → 自动退出回到状态1
   ▼ 配对成功(密钥持久化)
状态3: 已配对(日常常态,绝大部分时间)
       不再广播、不再扫描(对齐蓝牙配对后行为)
       已配对在线设备 → WebSocket 长连接常驻 + 30s 心跳
       已配对离线设备 → 每 60s 低频探测一次
       手动扫描按钮 → 临时进入状态2 扫描 30s
       每次启动 EM → 自动检查已配对设备在线,在线即自动连接
```

### 频率参数（对齐蓝牙指导值）

| 动作 | 频率 | 依据 |
|------|------|------|
| 配对期广播 | 每 2s | 蓝牙 <2.5s 可靠发现阈值（Apple Accessory Design Guidelines） |
| 配对期扫描 | 持续 | 桌面无省电限制（移动端低功耗占空比仅限 Android/iOS） |
| 配对超时 | 5 分钟自动退出 | 用户需求 |
| 长连接心跳 | 每 30s | WebSocket 标准心跳 |
| 离线设备探测 | 每 60s | 低频（对齐蓝牙后台节流量级） |
| 手动扫描 | 按钮触发 30s | 用户需求 |
| 启动检查 | 检查已配对设备在线并自动连接 | 用户需求（对齐 WiFi 记住网络） |

### 配对与安全

- **首次连接**：A 点选设备 → B 端弹窗"xx 请求连接"→ B 确认 → 双方交换并持久化密钥（会话密钥随机生成）
- **后续连接**：自动携带认证（密钥），免配对——对齐 WiFi 记住密码
- **配对管理**：设置页可查看/删除已配对设备（对齐蓝牙已连接设备列表）
- 传输加密：WebSocket + 密钥派生加密（或至少 TLS/自定义握手，实现时定）
- 设备身份：持久化 UUID，认 ID 不认 IP（IP 变化靠重新发现）

## 三、会话迁移协议（一次性）

```
【win 端 - 导出】
  选择项目 → 打包全部会话 jsonl → 生成会话包
  包内容: manifest.json(项目win路径/会话列表/EM版本/导出时间) + sessions/*.jsonl
  触发: 菜单"迁移会话" → 选目标已配对设备 → 发送

【局域网传输】
  经已配对设备连接,分块传输会话包(大文件走流式,不一次性进内存)

【mac 端 - 导入】(自动)
  收到会话包 → 弹窗确认目标项目(mac 上已存在项目或指定新路径)
  → 计算 mac 编码目录 → 放入 jsonl
  → 批量改写每文件首行 cwd: win路径 → mac路径(注意 JSON 转义 `C:\\Users\\`)
  → 完成 → 会话列表自动出现 → 点击即 resume
```

### 路径改写规则

- **只迁最新主会话 jsonl（1 个文件）**；subagents/ 目录不迁（执行完即无用，主会话内无引用）
- 只改首行 session 条目的 `cwd` 字段（JSON 解析后改值再序列化，不用字符串替换——避免转义陷阱，真实数据 `C:\\Users\\...` 是双反斜杠转义）
- win 路径 → mac 路径映射：用户在 mac 端选择目标项目路径时建立（纯前缀替换 + JSON 转义）
- 历史消息内工具调用的路径不改

## 四、项目迁移（纯手动模式,2026-08-08 定稿）

> 会话迁移只解决"对话记忆"，项目迁移解决"工作现场"。两者配合才是完整迁移。
> **用户定稿:纯手动操作——无 Mint skill / 无 MCP 迁移工具**。迁移由用户在设备面板手动完成。

### 发送端流程（源设备,手动）

```
用户: 设备面板 → 已配对在线设备 → 「发送」
    → 迁移对话框: 选项目 → 扫描清单(排除构建产物) → 确认
    → 主进程: 统一扫描 + 打包 zip + 两阶段握手 + 分块传输
【发送端职责止于"传输完成"——不感知对端落位细节】
```

### 接收端流程（目标设备,系统执行）

```
系统: 收到迁移包 → 弹窗"收到来自 XX 的迁移(项目+会话, 大小)"
用户: 确认接收 + 选择父文件夹(自动创建项目文件夹)
系统: zip 校验 → 缓存目录 → 解压落位(文件数必须匹配) → 会话恢复
     (cwd 改写 + 落盘验证,硬性保证会话文件有)
     → 迁移完成卡片: 模板文案(先说明"已迁移到另一台电脑,会话+文件完整")
       + 「复制并关闭」→ 用户粘贴发送给本项目 Mint,对齐上下文
     → 经互联通道回执给发送端(含 restoredCount/sessionRestored,双重确认)
```

### 完整性保障

- 发送端: 扫描校验(项目文件非空,会话存在——缺失打包失败)
- 传输: zip 整体 sha256 校验 + 两阶段握手(接收端确认后才传)
- 接收端: 解压文件数 === manifest.fileCount;会话声明则必须恢复成功(落盘+cwd 验证)
- 回执: restoredCount/sessionRestored 携带,发送端二次确认(不一致按失败处理)
- 失败: 缓存 zip 保留供排查 + 明确失败原因

### MCP 工具（builtin-mcp.ts,仅设备管理,保留）

| 工具 | 职责 |
|------|------|
| `list_devices` | 已配对设备（在线/离线）+ 可用设备列表 |
| `request_pair` | 向目标设备发配对请求 → 两端弹确认窗口 |

### 迁移清单规则

- **默认排除清单（单一实现,scanProject）**：`.git`、`node_modules`、`dist`、`build`、`temp`、`.idea`、`.vscode`、`.codegraph`、`.DS_Store`、`*.apk/*.exe/*.dmg/*.zip`、`.easymint` 可重建子项（shell-logs/templates/brand-tokens/group-sessions）
- **`.easymint/` 项目数据要迁**：state.json（任务状态）/run.json（运行配置）/issues.json（Issue 记录）——项目级 EM 数据，跟随项目走，**不在排除清单**；与"会话 jsonl"区分（会话走会话迁移通道）
- 清单格式：文件相对路径 + 大小 + 哈希，用于传输完整性校验
- **瞬时状态不迁**：打开状态/构建状态各端自持

### 传输包与校验

- 包带 manifest：来源设备/项目名/zip 哈希/文件数/会话文件名——接收端据此校验
- zip 整体 sha256 校验（先校验再解压,原子性）；解压文件数必须与 manifest 匹配
- **幂等**：恢复中断/失败可重新触发；失败保留缓存 zip 供排查，回执只在完整恢复后发出

## 五、技术选型（成熟方案，不自行发明）

| 层 | 技术 | 说明 |
|----|------|------|
| 发现 | mDNS 周期通告（`bonjour-service` Node 库） | 与蓝牙广告同构；桌面端无后台节流限制 |
| 连接 | WebSocket（`ws` 库），主进程服务端+客户端 | 局域网直连；心跳 ping/pong |
| 消息集 | JSON 小消息（hello/device-info/transfer-request/accept/chunk/complete/pair-request/pair-accept） | 对齐 Peer-Signaling-Protocol 精简版 |
| 身份 | 设备 UUID 持久化（首次启动生成） | 认 ID 不认 IP |
| 架构 | 主进程 network-service，IPC 暴露给渲染层（contextBridge 严格边界，渲染层零网络知识） | 对齐 Aether Electron 安全模式 |

## 六、跨设备会话消息传递（未来扩展，本阶段只打基础）

当前通道（发现+配对+WS 连接）天然承载消息传递：

- 会话间实时互发：DataChannel 语义由 WS 消息承担（本阶段不做，仅协议预留 `message-send` 消息类型）
- 设备间通知（Agent 完成/会话更新）→ 同一通道
- 接力继续：同步层已保证数据一致，B 上直接打开即可

**瞬时状态不同步**：打开状态/构建状态各端自持（win Mint 建议，已采纳）。

## 七、工程要点（win Mint 实战建议，已验证采纳）

1. **发现与同步解耦**：发现只负责建连，数据靠连接内传输——离线期间的会话包一次补齐
2. **LWW/时间戳即可，不上 CRDT**：会话是 append-only jsonl（事件日志模型），追加+按(时间戳,设备ID)排序
3. **防回声**：多设备互相转发必须"仅实际变更才转发"（本阶段单包传输无此问题，消息传递阶段必须遵守）
4. **版本号取 max 不取 max+1**（防版本膨胀破坏删除同步）
5. **联调脚本驱动真实网络栈**：node 起多实例模拟多设备（本项目 48→181 项断言抓出 10+ bug 的经验）
6. **平台坑**：win 防火墙放行监听端口、mac 沙盒 entitlements（如启用）、路径/换行符差异

## 八、验证计划

1. **resume 可行性验证（先行）**：写脚本复制 win 会话 jsonl → 改写首行 cwd 为 mac 路径 → 用 Pi SDK `SM.open` 恢复 → 确认会话可读、可继续
2. **多实例联调**：node 起 2-3 个虚拟实例（模拟 mDNS 发现 + WS 配对 + 会话包传输）跑通全流程
3. **真机验证**：win 导出 → mac 导入 → 会话列表出现 → resume 正常

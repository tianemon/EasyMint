## 三、关键约定

### 3.1 路径规则

| 路径 | 说明 |
|------|------|
| `~/.easymint/` | **全局**配置目录（开发期隔离原版） |
| `<project>/.easymint/` | **项目级**数据（与 EM 原版一致） |

### 3.2 Pi SDK 使用规则

```
所有 Pi SDK import 都通过 pi-sdk.ts 懒加载（ESM → CJS 动态 import）
  ✅ import { createAgentSession } from "./pi-sdk"
  ❌ import { ... } from "@earendil-works/pi-coding-agent"
  
type-only import 可以直接用（esbuild 擦除）
  ✅ import type { Model } from "@earendil-works/pi-ai"
```

### 3.3 新增 Pi 原生能力

如果需要 Pi 的新 API，先查 `docs/reference/Pi-SDK-API参考.md`。Pi 原生已有但 EM 未用的功能（如 `executeBash`、`getSessionStats`），直接在 backend → IPC → preload → 前端接上。

### 3.4 omp 移植流程

如果需要 omp 的能力但 EM 没有：

1. 检查 `vendor/omp/` 是否已有源码
2. 复制到 `services/omp/` 对应目录
3. 替换 Bun API（对照 `vendor/omp/CHANGES.md`）
4. 替换 `@oh-my-pi/*` 引用（logger → console, isRecord → inline, 等）
5. 创建 stub 处理 omp 内部依赖（`../capability/*` 等）
6. `npm run build:main` 验证

### 3.5 omp 升级

```bash
# 1. 覆盖 vendor
cp -r /path/to/new-omp/packages/.../src/ vendor/omp/

# 2. 看 diff
git diff vendor/omp/

# 3. 只关注 changed files，对照 CHANGES.md 重新 apply 修改
#    90% 的情况只需全局搜索替换 Bun API（见 CHANGES.md）
```

## 五、常见问题

### Q: 构建报 ESM/CJS 错误
A: 检查 esbuild 的 `--external:` 列表是否包含新依赖。`package.json → build:main`。

### Q: 前端事件收不到
A: 检查 `event-bridge.ts` 的事件类型映射、`agent-service.ts` 的 `broadcast()` 调用、preload 的 IPC 监听器。

### Q: Pi API 调用失败
A: 确认 `pi-init.ts` 的 `registerProvider` 中 `reasoning`、`cost`、`input` 三个字段已填写（Pi 强制要求）。

### Q: omp 的 import 找不到
A: 检查是否已做 Bun → Node 替换 + @oh-my-pi 引用替换 + stub 文件创建。

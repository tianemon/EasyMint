# UI 场景与动态验收要求

本轮不以“组件齐全”“功能能点”为成品标准。每个模板先定义使用者、任务、视觉主角、动态行为；实现与导出的 HTML / CSS / runtime 使用同一份源码。运行需求写入 scene-contract.json 与 DESIGN.md，供 Mint 实际参考。

## 赛博朋克：NEXUS 全球边缘网络监测台

用户是一位网络运维人员，需要快速知道网络是否正常、观察跨区域信号、选择中继检查链路，并发起扫描。视觉参考为归档的 22-hud 动效。独立绘制界面和动画，不直接嵌入原作品。地理轮廓来自 Natural Earth 公共数据，经简化后内嵌；保留 world-atlas 的 ISC 声明。

- 近黑底、青蓝荧光、冷白数据，严格不加入紫色。
- 中心地球为主角，左右窄栏负责流量、中继与性能，导航和标题退到第二层。
- 霓虹：发光线框海岸、透视地面、精密径向刻度、沿路径移动的信号。
- 全息：点阵陆地、体积明暗、悬浮斜轨道与扫描光层。两者在静帧和运行时都必须有明显差别。
- 点击中继后，选中态、相机朝向、节点观察信息和锁定反馈同步变化。
- 扫描有“探测中继 → 追踪路径 → 信号锁定”的过程，期间按钮显示忙碌状态，结束有结果提示。
- 数据明确标记为模拟；实时变化用于解释“正在观测”，不伪装生产服务。
- 目标 30fps，上限 2x DPR；画布随容器测量，隐藏/离屏停止帧循环，卸载释放观察器和事件。减少动态效果偏好下保留静态可用界面。

## 自验标准

1. 先以真实使用场景看首屏：主角清楚，关键信息可读，小预览能看到风格特点。
2. 同尺寸、同状态对比效果切换，静帧也能辨认；拒绝仅更改一点阴影/颜色。
3. 检查动态的开始、过程、结束；没有触发就不应播放的动画不能常驻。
4. 点击每个菜单，内容和任务必须变化；返回时保留用户输入和合理状态。
5. Web / 移动端重排后仍符合构图；减少动态效果时不丢内容或操作。
6. 类型、测试、构建通过只证明技术检查；必须另外看真实渲染、运行与交互。

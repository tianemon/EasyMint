# 快速原型

## 适用与授权（G3/G4）

极简/简单/无 UI 项目跳过 UI 原型。其余先制作原型供用户确认；原型验收后才写完整需求、架构和 task.json。

先核对核心功能、用途、风格、范围及已有授权。用户已同意按这份需求制作原型时，一句说明就开始，亲自或委派均不重复问“开始/可以吗”。确有改变范围的缺口或尚无制作许可时，将理解与必要取舍合并一次确认。**同意制作不等于看过成果后的验收，不代替正式开发批准。**

精度按实际用途确定：商用覆盖核心流程、状态、异常及响应式；实际使用突出核心操作；兴趣强调视觉探索；验证想法突出可试的路径。认知不降低工程要求，无 UI 技术实验不加界面。

## 视觉起点与委派

- 有 VisualSpec：默认 `showcase`，先读项目 `.easymint/design/DESIGN.md`、`scene-contract.json`、双端 showcase，再定位相关 CSS/runtime。预设复用真实构图与材质；brief 模式以用户描述为主，基础场景仅供可选参考。原生目标按 PORTING.md 转译，HTML 不是原生实现。
- 只需固定版式骨架时显式指定 `模板：<文件名>`，只借结构；四类为 landing/dashboard/form/detail，优先项目 `.easymint/design/templates/`，旧项目 `.easymint/templates/`。没有既定方向可 `自由设计`，给具体方向；不让子代理漫无目的翻模板。
- 需要时按 ui-aesthetic 的已知位置读取当前相关部分；不重选已有品牌/风格，不将风格简化为配色。不为局部修改重做整站。
- 按 creation-guide 的独立执行判据决定亲自或委派 Mint-D。委派包含真实功能、平台/比例、方向、文件路径、已选规范与需验证的状态；子代理不再向用户确认。

## 展示前检查

检查 prototype/index.html：hidden 不被 display 覆盖；CSS 变量无自引用/未定义；标签配对；浮层默认隐藏且层级正确；首屏内容、文字对比正常。

有渲染能力时查看真实页面和关键交互，发现问题先修；不可渲染/读图时说明仅做源码检查，不宣称视觉验收。用户仅要求打开已有预览时直接 show_prototype，不夹带新一轮审查。

## 首次交付与反馈

调 show_prototype 展示。结合实际实现给一条核心试用路径，例如“添加一笔，再按分类查看”；说明本轮可验证能力、模拟数据和未验证范围，不笼统认定原型一定不能存数据或已经是成品。邀请用户指出具体不符合预期的地方，再取得 G4 验收。

“太挤/不好看”时先对照页面分析主次、间距和操作；已明确要保留的颜色、布局继续保留。方向不足才给少量有差异的选择，不要求专业评审。用户说“没反应”时先查可得代码/日志与当前入口；确实缺证据才补问关键操作，不假装看见屏幕或责怪提示词。连续修复无效需重核目标、复现和假设。

小改由 Mint 直接处理；结构重排可重新委派，携带已有决定。修改后做针对性检查再展示；范围变化时确认受影响内容，不重新采集整套表单。用户验收后读 creation-flow-techspec，落完整文档并按实际 Gate 进入开发。

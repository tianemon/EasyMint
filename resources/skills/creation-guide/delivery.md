# 运行与交付判定（条件式——检测到分发意图才追问）

> 默认**不追问**交付细节（多数用户自用工具，收尾给运行方式即可，保持引导精简）。
> 需求采集中出现分发信号时进入本节——大白话追问 2-3 个问题，技术方案由你判定，不向用户解释技术细节。

## 分发信号（按意图分类，任一说法命中即触发）

| 意图 | 信号（常见说法） |
|---|---|
| **给他人用** | 给朋友/同事/家人用、给大家用、分享、发布、开源、卖、给客户/甲方 |
| **多人/团队用** | 团队用、公司里用、部门用、多个人一起用 |
| **网络/远程访问** | 放网上、别人打开网址就能用、远程访问、部署到服务器 |
| **软件形态** | 打包、安装包、做成软件/exe/app、双击就能用、上架、应用市场 |
| **移动端** | 手机上用、装到手机、安卓、苹果 |
| **特殊环境** | 老电脑、对方没装环境、对方不懂电脑 |

## 触发后的追问（大白话，用户能感知的问题）

1. 主要给谁用？（自己 / 身边人 / 公开发布）
2. 用的人大概在什么设备上？（Windows / Mac / 手机 / 网页访问——对方设备较老时确认大致年代）
3. 希望对方怎么拿到工具？（双击打开就能用 / 要安装 / 网页访问就行）

## 交付形态判定（用户回答 → 选型与收尾依据）

| 用户意图 | 交付形态 | 收尾输出 |
|---|---|---|
| 自己用 | 无需打包 | 运行面板一键运行即可（生成 run.json） |
| 给身边人 | 简单分享 | 按技术栈打包成单文件或安装包，给出一句「发给对方后怎么打开」说明 |
| 公开发布 | 标准分发 | 完整打包 + README 使用说明；Web 项目给静态部署/托管方式 |

## 选型约束（用户提到特殊环境时）

- **老系统**（Win7/老旧硬件）：选型避开依赖新版 WebView / 新版运行时的方案，优先原生兼容
- **体积敏感**：优先轻量方案，避免捆绑大运行时；桌面 UI 优先轻量框架
- **对方无技术背景**：默认「双击能用」优先于「功能最强」——宁可多打包一步，不给对方命令
- **Python 工具要分发**：默认引导 PyInstaller 打包单文件 EXE（对方双击即用），不让对方装 Python 或输命令启动

> 以上约束只影响你的选型与收尾动作，不转化为向用户解释的技术问题——用户只需要回答「给谁用、什么设备、怎么拿到」。

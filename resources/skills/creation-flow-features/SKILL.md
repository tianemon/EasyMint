# 功能共创

沿用已采集功能，不重新让用户列一遍。缺细节时先给可修改草案；目标大时推荐一版能实际使用的核心流程，说明理由，不擅自删掉用户明确要求。

- 按用户故事标注 P0（没它不成立）/P1（核心体验）/P2（锦上添花），每项可验收。用户决定业务效果，Mint 负责实现选择。
- 用户问 MVP 才按本项目解释：先完成哪条可用流程，哪些暂缓；MVP 不允许核心功能失效。
- 只确认真正未定的范围；已认可的同一清单不反复确认。本阶段不落完整文档；适用 UI 项目在原型验收后落需求、架构与 task.json。
- 对照实际部署、成品 AI 和预算，风险或冲突才读 creation-flow-cost。未填写不当作明确选择，不凭“云端/AI”标签就断定必然付费。用户混淆时说明成品 AI 与 Mint 帮助开发是两回事。

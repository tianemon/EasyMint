# EasyMint 运行环境与功能讲解

用来回答"它是怎么工作的"这类问题。**讲机制讲准确，讲界面位置以当前版本为准** ——
界面会改，机制不会天天改。用户问什么答什么，别铺开讲整套架构。

## 一、运行环境

| 项 | 事实 |
| --- | --- |
| 形态 | Electron 桌面应用（Windows / macOS / Linux），不是网页服务 |
| 会话引擎 | 内置 Pi coding agent（`@earendil-works/pi-coding-agent`），主进程直接跑 AgentSession，不经外部 AI CLI |
| 进程 | 主进程（窗口、服务、会话编排）· 渲染进程（界面）· preload（IPC 桥）· 记忆库独立 worker 线程 |
| 会话文件 | `~/.easymint/agent/sessions/<编码后的项目路径>/<会话ID>.jsonl` |
| 数据目录 | `~/.easymint/`：`agent/`（会话、技能）· `memory/`（MEMORY.md、来源/检索索引、事务恢复文件）· `experiences/`（经验库）· `managed-skills/` · `mcp.json` · `em-settings.json` |
| 联网 | 模型与搜索都需要网络；主进程 HTTP **不自动跟随系统代理**，应用启动时自己接管系统代理设置（可用 `EASYMINT_NO_SYSTEM_PROXY=1` 关闭） |
| 单实例 | 同一台机器只跑一个实例；关窗口默认最小化到托盘，后台任务继续 |

## 二、会话与上下文

- **一次会话 = 一个长期 AgentSession**。历史以 jsonl 落盘，界面上的折叠、分组只是展示，不改文件。
- **核心与角色**：内核维持目标、执行、协作、验证、记忆和权限职责；人格负责身份与表达，模式补充方法。用户可在实际权限内选择本次的讲解、进度、委派和记忆方式。昵称取角色设置，默认人格不写死昵称；未自定义的旧默认按精确指纹更新，用户内容保留。
- **角色与协作模式设置**：Agent角色页直接编辑主对话的头像、昵称、人格和规则；Builder/Evaluator仍只编辑其规则正文。协作模式可在创建会话前叠加选择，创建后及恢复时选择固定；不提供会话中的启用模式按钮。模式集合固定不妨碍用户直接要求不同讲解深度。
- **上下文每轮重新组装**：内置Agent职责 → 角色补充（昵称/人格/模式）→ 适用项目规则 → 项目环境 → 视觉契约 → 权限段 → 工具与技能目录。内容不变时逐字相同，所以能命中模型缓存。
- **两条投递通道**：稳定内容进系统提示词；会话期内会变的内容（记忆、提醒）**追加在当前用户消息之后**，前缀一个字都不动 —— 这是为了不破坏缓存。
- **压缩**：上下文接近窗口上限时自动整理历史；压缩后关键内容（如记忆）会重新注入一次。
- **子 Agent**：用于独立复核、并行方向或长上下文隔离；模板只定义角色，模型与思考等级跟随主会话。

## 三、记忆（这是最容易被误解的部分）

**它不是聊天记录，也不是把对话存一份。** 它只做一件事：让下一次开口不用重复交代。

- **存在哪**：`emHome()/memory/MEMORY.md` 是近期浅层正文，整体约8000估算token；较早凝练详情放在 `memory/deep/YYYY-MM-DD/MEMORY.md`，按记忆最近实质更新日期分目录。经验独立存 `experiences/<稳定ID>.md`。SQLite仅保存位置、版本、来源、资格、检索与后台状态，不保存另一份正文。路径沿用用户配置的数据目录。
- **什么时候写**：Agent在工作中主动识别值得延续的事件、持续事项、重要决定和特殊环境，用memory提交；经验证的条件/方法/边界用experience提交。用户也可以直接说记住、更正、整理或忘记。真实结构化提交直接保存，不再安排模型审核一遍。
- **后台做什么**：每小时在前台空闲时补漏新完成回合；包含实际执行的子会话，沿用实际模型、父任务权限及证据。无新增不调用模型，已主动提交的内容不重复提炼；前台活动抢占后保留到期任务，空闲再续。启动/恢复只补一个到期机会，写后用代码检查容量，不推迟小时调度。
- **不写什么**：普通操作、一次性日志/代码原文、凭据、已有文档能直接查的常规事实。人格和表达风格归角色配置，人工开发规则归项目已有AGENTS/同类入口；经验不自动改规则或创建技能。开发记录仍是项目进展主源，由执行Agent维护，后台不另写一份。
- **怎么读**：适用的浅层全局/当前项目内容在当轮用户消息之后增量提供，不能改系统前缀；新会话/压缩后按真实上下文余量重新交付。旧理由、详情或相似问题由Agent主动搜索，先少量结果，再按ID分页读正文，单次默认约1500估算token；不读整天目录或全库。
- **怎么整理**：代码先把较早详情无损下沉，必要核心可留在主MD；不必给每条深层永久保留摘要。移动/读取不刷新记忆日期，移动也不代表事实失效。新事实更正沿用ID并保留有意义旧版本；明确到期、被推翻或用户要求转历史才改变有效性，没有年龄评分或自动退役。
- **如何控制**：记忆页直接展示只读主MD正文及两个滑动开关，正文随更新刷新，无数据库/经验条目管理页面。后台整理默认开启，保留用户明确关闭的选择；总开关关闭时不会运行后台模型。关闭后台仍能主动提交及代码容量保护。明确遗忘清除浅/深层及相关索引并阻止旧来源重提取。删除会话默认保留已生效结论并标记来源不可访问。
- **故障与首次上线**：多文件写入有中断恢复；新格式正文存在而索引缺失时保留正文、停止采用并提示恢复，不能当空库覆盖。首次上线由程序一次性清理可识别的旧记忆与旧经验，不导入旧经验，也不回溯提炼旧会话；只处理启用边界之后开始的新回合。后续重启不重置新记忆，项目文档、原会话与自定义角色配置保留。
- **当前信息**：开发记录→仓库/文件证据→近期会话路标的项目进展降级链保留；易变端口/进程等现场查询。本机特殊长期条件可以作为记忆。其他工具会话默认只发现同项目元信息，需要时才按受控引用读结论。

## 四、项目、任务与技能

| 概念 | 是什么 |
| --- | --- |
| 项目 | 一个真实目录。EM 记录路径与最近打开时间，不接管你的文件 |
| 待办（用户） | 跨会话的想法清单，`.easymint/todos.json`，界面"待办"面板可改 |
| 会话 todo | 当前这一轮的执行阶段，不逐条工具回填 |
| 正式任务 | `task.json`：交付项、依赖、验收状态。普通"改一下"不自动建 |
| 开发记录 | 项目内的进度真相源（导航 + 按日期明细）。**由 AI 在阶段收尾时直接写**，应用不生成 |
| 技能 | 按需加载的方法与资料。默认只有名字和描述常驻，正文用到才读 |
| 经验 | 经真实证据支持的条件、方法、验证与边界；独立主题MD，通过experience按需检索，不自动升级规则或技能 |

## 五、模型与供应商

- 供应商与模型在设置里配，密钥存在本机；会话绑定创建时选定的模型，切换按当前配置生效。
- 输入框下方可看**上下文使用率**与余额；余额来自供应商，与"这次任务花了多少"不是一回事。
- 子 Agent 不会另配供应商，跟随主会话。

## 六、权限与安全

三档，含义是"AI 能自己做到哪一步"：

| 档位 | 边界 |
| --- | --- |
| **只读** | 仅浏览项目内容，不执行、不写入、不联网；白名单式放行，凭据也不可读 |
| **标准** | 在系统沙盒内开发；写文件与命令需要授权，只对"不含 shell 操作符的单一命令"免询问 |
| **完全访问** | 不套沙盒，普通文件不受工作区限制；切换要确认，标识为玫红警告 |

- 沙盒按平台：macOS 用系统 seatbelt、Linux 用 bwrap，Windows 使用受限令牌与 Job Object；具体可用性与降级说明以当前会话状态为准。
- **权限 ≠ 授权**：权限决定"能不能做"，授权决定"这件事能不能做"；记忆与历史背景都不构成授权。
- 忘记、删除会话、切换完全访问这类动作都要求明确意图，不会被静默执行。

## 七、设备与手机

- **设备互联**：同一局域网内手动配对（mDNS 发现 + 加密通道），可把项目连同样例会话迁移到另一台机器。
- **手机端**：既有 App，也能用手机浏览器访问本机服务；适合在外面查看进度、发一句话让 AI 继续。

## 八、几个常见误解

| 误解 | 实际 |
| --- | --- |
| "它记得我们聊过的一切" | 只记压缩后的结论与约定；原话只在会话文件里，需要时按来源查 |
| "记忆是模型自己长的" | 记忆正文保存在本机，交给 Agent 维护；设置里可查看、关闭 |
| "项目进展是它总结的" | 多数时候读的是项目自己的开发记录 |
| "给了完全访问就等于同意任何操作" | 权限只是门槛，具体动作仍按授权与预检执行 |
| "余额掉得快就是记忆在偷跑" | 主要成本是主会话上下文；后台仅分析新完成的轮次，按模型容量分批；没有周期性重读全会话或额外总结模型 |

# 风格工艺与诊断

这是处理风格同质化、材质粗糙、移动端简陋时的参考，不要求每次把所有手法都用一遍。用户选定的方向和项目样式包优先。

## 六种风格的差异不止颜色

| 方向 | 布局与形状的判断 | 组件与材质的判断 | 常见失真 |
|---|---|---|---|
| 极简 | 内容的比重、精确对齐、行宽与留白形成秩序；列表/分组不必都包卡片 | 安静表面、轻量分隔、字重和空间承担层次 | 只剩黑白空白，内容被删薄；所有动作都藏成无标签图标 |
| 扁平 | 硬朗的几何、清楚的色块、编辑式标题与大胆比例；适合时可用海报式构图 | 形状/字重/边界区分状态，避免浮雕和漫反射投影混进来 | 同一个圆角后台改个红色；为了“高级”又加渐变、玻璃和软影 |
| Material | 操作层级与导航清楚、信息组织稳定，容器和留白与内容密度匹配 | 表面抬升、形状体系、可见交互反馈；表单/菜单/状态属于同一体系 | 每张卡都同高同影，主次不分；换绿色就自称Material |
| 玻璃 | 背景与前景的层叠关系、克制而有方向的光源；内容仍是主体 | 可透出的背景、透明度、背景模糊、边缘光和接触影共同成立；菜单/弹窗延续材质 | 灰色半透明矩形叠在纯色上；只有主卡模糊，菜单还是原生；白字hover成白底；blur创建堆叠上下文后菜单被后续卡片盖住 |
| 新拟态 | 连续底材、较充裕的间距、适合的实体控制形态；避免全页凹凸铺满 | 成对且方向一致的高光/暗影，抬起与按下有区分；输入凹、按钮凸 | 对比过低、边界不可辨；把每个元素都做成大枕头，状态只剩颜色 |
| 拟物 | 有明确现实参照的部件比例、纸张/金属/实体旋钮等构造 | 光照、接触、纹理、边缘与状态相互解释；不依赖棕木色才成立 | 所有东西换成棕色；随手加渐变和重影；结构仍是另一种风格 |

混合风格需要明确主次和功能理由；不要把六种材质随机拼在同一页，也不要将本表变成所有产品必须使用的装饰清单。

## 从这轮打磨中提炼的诊断方法

### “太蓝 / 太黑 / 单调”

先看画面是否缺少内容尺度、视觉节奏或材质差异，再决定配色。把整屏蓝换成整屏黑不会改善构图。可通过真实作品、主次栏宽、标题与正文比例、局部有意义的色块建立重点，而不是增加三个装饰渐变。

### “只有换色，没有风格”

做一次去色判断：圆角/轮廓、字号与字重、留白密度、光照/纹理、控件状态和布局节奏有没有变化？在现成样式包中找相应组件与装饰结构，不要只手写新CSS值。切换扁平到玻璃却保留原海报结构，不能当成已同步完成；未编辑装饰才自动迁移，用户修改须合并。

### “看起来精致，但不想用”

找用户第一步动作需要经过的视线与手指路径。删去无帮助的说明、重复标题和假统计；保留必要标签、错误恢复与主动作。把文案、字段和示例换成当前产品真正要处理的内容。控件展厅要能探索，不需要一个“浏览组件”的装饰性入口。

### “细节像拼起来的”

只看一组常用组件：按钮、输入、单选/复选、下拉、菜单、弹窗。它们的轮廓、材质、文字对比与状态是否连续？打开菜单、选另一个选项、重开并检查选中；用键盘进出并返回触发点；用真实pointer确认没有透明层挡住。原生滑块/下拉、裸色弹窗是常见漏网项。

### “移动端只是桌面的缩略图”

先把手机上的主任务与单手动作排出来，再重排导航/作品/列表和辅助信息。保留气质但减少同时竞争的元素；窄屏重视任务顺序，阔屏利用额外宽度，横向注意可用高度。不要用360px固定宽度把阔屏中央缩成一条；不要为了漂亮截图裁掉真实交互。

### “提示很显眼，却更难操作”

检查提示是否在文档流里挤动历史/导航，或作为浮层遮住输入/焦点。按职责区分提示与工作区：降低重复文案权重，缩减不必要的占幅，靠近相关动作但让已有入口位置稳定。只在内容真正变化时改变布局，hover和初始渲染不应出现临时矩形块。

### “预览好看，实际结果变样”

追踪选择→项目规范→真实CSS/装饰结构→主/子Agent→目标页面，不能只证明提示词里出现了glass。抽查实际文件与渲染状态；还要走一次编辑器保存、再次换风格、保留业务正文。HTML序列化会改变空属性写法，不应被误判为用户改了主题；读到文件不等于已复用它。

## 有分寸的验证

按变化选择少量最能区分对错的场景：
- 配色/材质变化：正常与hover文字对比、菜单/弹窗材质、一个浅色和一个深色表面。
- 组件交互：选中与焦点、错误/禁用/加载、外点/Escape、滚动/缩放后定位。
- 版式变化：首屏主次、一条真实内容较长的列表/标题、长屏与阔屏的布局。
- 设计同步：页面实际结构、样式文件来源、用户编辑/保存再更新路径。

同时看截图和使用动作。色值、可见性、位置与交互可测；“高级感”是结合产品、内容和用户反馈的设计判断，不伪造一个审美分数或通过率。
